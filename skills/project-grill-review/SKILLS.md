# 方案拷问类 Skill

用于对君航 AI 助教项目中的方案、架构、功能设计、迁移计划、AI 工作流或实施步骤做压力测试。`grill-me`、`grilling`、`grill-all` 是外部可选增强；本文件是项目本地化规则和唯一必需入口。

## 适用场景

- 用户说“grill me”“拷问我”“挑战这个方案”“压力测试一下”“仔细想想风险”。
- 实施前需要确认方案是否符合多端优先、服务层优先、教师复核、Git 可追踪和验证边界。
- 计划涉及小程序、资料上下文、生成/批改、学生档案、外部 skills 或第三方 API。
- 需要在写代码前拆出风险、依赖、验证命令和人类决策点。

## 可选外部 Skills

- `grill-me`：来源为 `mattpocock/skills` 的 `skills/productivity/grill-me`；用于触发严厉追问模式。
- `grilling`：来源为 `mattpocock/skills` 的 `skills/productivity/grilling`；用于一问一答式追问，直到共同理解清楚。
- `grill-all`：来源为 `zhjai/grill-all` 的 `skills/grill-all`；用于 source-aware 计划审查，先把问题路由到用户、项目文档、代码库或 Web。

外部 Skill 是否在当前任务可见必须以当前 Skills 列表为准；不可见时仍按本项目 Playbook 执行，不假设重启一定生效，也不影响将本文件作为唯一必需入口。

## 工作模式

### Grill-heavy 模式

用户明确要求“拷问”“grill me”“一直追问”“压力测试”时使用。

- 一次只问一个问题。
- 每个问题先说明已经检查了什么。
- 每个问题必须给出推荐答案。
- 用户回答后再进入下一层依赖问题。
- 在达成共同理解前，不实施方案。

### Autonomous review 模式

用户要求“直接推进”“你按想法操作”“不要频繁问我”时使用。

- 优先查项目文档、代码、测试和官方资料。
- 低风险、可逆的假设可以记录后继续推进。
- 只在产品方向、风险接受、权限边界、成本消耗或不可逆操作上提问。
- 提问仍然一次只问一个问题，并给推荐答案。

## 问题来源路由

每个未解决问题先分类：

1. 当前用户指令已经明确：直接遵守，不重复问。
2. 项目规则或产品边界：先读 `AGENTS.md`、`SKILLS.md`、`docs/51-project-pitfall-review.md`、`docs/52-workspace-guardian.md` 和相关模块 `SKILLS.md`。
3. 当前实现事实：查代码、API、测试、脚本、类型、调用点和已有运行手册。
4. 第三方或近期能力：查官方文档、GitHub 仓库、API 说明或 primary source。
5. 用户意图或取舍：向用户提问。

不要把代码库或文档能回答的问题抛给用户。不要让 Web 搜索覆盖项目规则。

## 本项目固定审查维度

每次 grill 或计划审查至少覆盖：

- 多端边界：是否仍以小程序、课堂平板、公共屏为最终方向，Web 是否只是验证入口。
- 服务层边界：核心逻辑是否在 API、服务层、脚本、共享工具或数据契约中。
- 可见性边界：学生、家长、课堂平板和公共屏是否隐藏模型、供应商、内部 prompt、调试字段和需要教师复核但尚未确认的内容。
- 任务级复核：学生 AI 问答是否在服务层处理后即时返回；问答学习信号是否满足身份、安全、结构和成功返回准入；生成、批改及正式档案输出是否进入教师确认流程。
- 数据与产物：上传资料、导出物、截图和运行产物是否默认本地保存，不误纳入 Git。
- 验证命令：是否有最小验证命令，不用完整 E2E 替代小范围检查。
- Windows 命令：是否使用 `cmd /c npm.cmd run ...`、显式 Python 版本和短命令。

## 输出格式

需要拷问时：

```text
我检查了：...
当前未解决的人类决策是：...
我推荐：...，原因是 ...
问题：你选择 A、B 还是 C？
```

需要自主审查时：

```text
我检查了：...
结论：...
低风险假设：...
需要用户决定：...
下一步验证：...
```

需要实施前收口时：

```text
成功标准：
1. ...
2. ...

风险：
- ...

验证：
- ...

不做：
- ...
```

## 禁止项

- 不一次问多个问题。
- 不问项目文档或代码能回答的问题。
- 不用“拷问模式”拖住低风险实现细节。
- 不在未确认前执行高成本模型调用、批量 stage、发布、删除或不可逆操作。
- 不把用户的一次性偏好写成项目永久规则，除非用户明确要求写入文档。

## 验证

- 修改本 skill 或相关中文规则后运行 `cmd /c npm.cmd run check:encoding`。
- 计划审查本身通常不需要跑大型 E2E；只有进入代码实现后，才按改动范围选择对应验证命令。
