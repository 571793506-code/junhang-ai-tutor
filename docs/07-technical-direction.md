# 技术方向建议

## 推荐路线

先用 Web 模拟端跑通业务，再适配小程序。不要一开始直接进小程序，否则调试 AI、数据、页面和权限会被微信生态限制拖慢。

## 前端

- Web 模拟端：Next.js 或 Vite + React。
- 小程序端：后续根据页面定稿选择原生小程序、Taro 或 uni-app。
- 教学实验室：独立 Web 端，使用 React + Three.js。

## 后端

- Node.js / TypeScript。
- API 层统一承接学生端、家长端、老师端和模型服务。
- 后续可拆分为任务队列、文件处理、模型调用、报告生成等服务。

## 数据库

首选 PostgreSQL，适合结构化学生数据、行为日志、知识点和报告记录。

可选组合：

- PostgreSQL：主业务数据。
- 对象存储：图片、PDF、PPT、音频、3D 资源。
- 向量库：教材片段、知识点、历史问答检索，第二阶段再上。

## AI 编排

- `packages/ai` 负责模型适配、prompt、skill 调用和输出校验。
- 每次 AI 调用都记录 `model_runs`。
- 重要输出要有结构化 schema，尤其是批改、错因、报告和题目生成。

## 质量控制

- 题目生成要有答案与解析自检。
- 批改低置信度时进入老师复核。
- 家长报告必须基于真实学习记录，不生成空泛评价。
- 学生端回答要按年级降维解释。

## 安全与隐私

- 学生信息最小化采集。
- 家长、老师、学生权限分离。
- API Key 不进入前端。
- 图片、作业、报告后续需要设置访问权限和过期链接。
