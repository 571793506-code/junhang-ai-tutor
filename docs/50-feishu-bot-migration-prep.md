# 飞书机器人新项目迁移准备

本文记录从“君航 AI 助教”当前多端系统转向“飞书机器人轻量项目”的迁移边界。小程序搭建暂停，后续除非明确要求，不继续推进小程序页面、路由、样式和端侧交互。

## 1. 当前判断

当前仓库已经沉淀了较多服务层、AI 调用、资料上下文、学生档案、生成与批改经验，但工作区很脏，且生成类、批改类存在明显质量和耗时问题。新项目不应直接复制当前复杂链路，而应选取稳定经验，重新做一个更小、更可控的飞书机器人。

飞书机器人定位：

- 先服务老师，不直接服务学生和家长。
- 以群聊或私聊指令触发能力。
- 输出以文字、卡片、文件附件和可复核草稿为主。
- 老师确认前，不把 AI 结果当作最终结论。
- 不把模型名、供应商、内部路径、密钥或调试字段暴露给普通用户。

## 2. 适合迁移的 Skills

建议新项目优先使用这些能力：

- `junhang-ai-workflow`：保留资料上下文、结构化生成、教师复核、验证边界这些工程经验。
- `document-markdown-ingestion`：用于老师上传讲义、资料、PDF、Word、图片后的 Markdown 化和索引准备。
- `pdf`：只在确实需要读 PDF、检查 PDF 或导出附件时使用；不作为首期核心。
- `a4-exam-pdf-layout`：只保留 A4 输出经验，不迁移当前复杂试卷生成主流程。
- `openai-docs`：仅在需要确认 OpenAI API 或 Codex 最新官方用法时使用。

暂不主导使用：

- `browser` / `chrome`：飞书机器人首期不做复杂 Web UI 验收。
- `imagegen`：首期不做图片生成主链路。
- `documents` / `spreadsheets` / `presentations`：除非老师明确要求导出对应 Office 文件。
- 生成类和批改类相关插件能力：只做辅助检查，不做主创作或主判断。

## 3. 模块迁移选择

### 3.1 AI 问答类

可迁移内容：

- `packages/ai/src/runtime.js` 中 AI 问答的提示词边界经验。
- `packages/services/src/index.js` 中 `answerStudentQuestionService` 的服务层封装思想。
- “AI 只做思路引导，不直接替老师下最终判断”的产品边界。

新项目建议形态：

- 飞书指令：`/问答 年级 学科 问题`
- 输出：简短解释、分步骤思路、注意事项、是否建议老师补充。
- 不做学生端沉浸式对话，不做小程序页面。

### 3.2 学生档案类

可迁移内容：

- 学生档案草稿只作为教师可编辑草稿。
- 档案来源要标注：任务、批改、问答、课堂观察。
- 发布前必须由老师确认。

新项目建议形态：

- 飞书指令：`/档案 学生名 近7天`
- 输出：学习表现摘要、优势、薄弱点、建议动作、需要老师补充的信息。
- 首期可用轻量 JSON 或 Markdown 文件保存，不急于迁移完整数据库结构。

### 3.3 教材资料类

可迁移内容：

- 普通资料转 Markdown。
- 内容索引、章节摘要、知识点提取。
- 资料进入生成或问答前必须有来源记录。

新项目建议形态：

- 飞书上传文件后，机器人登记资料。
- 老师用指令确认资料用途：`/资料 入库`、`/资料 搜索 关键词`。
- 首期只处理普通 PDF、Word、PPT、图片和文本；不改写受保护教材文件。

### 3.4 生成类

只迁移创作模块经验，不迁移当前完整实现。

保留经验：

- 先识别内容类型：小测、练习、试卷、任务、讲解、家长反馈。
- 模型输出只作为草稿。
- 使用结构化字段：标题、目标、题型、答案、解析、注意事项。
- 老师确认后才导出或发布。
- 可参考教材单元和老师资料，但题目必须原创。

暂不迁移：

- 当前 PDF 自动排版链路。
- 当前多模型审查堆叠。
- 当前自动修复到最终 PDF 的流程。
- 当前未稳定的英语小测/练习/试卷模板实现。

新项目首期建议：

- 飞书指令：`/生成 小测 五年级英语 第四单元 要求...`
- 输出：Markdown 草稿，不直接生成正式 PDF。
- 老师确认后，再考虑导出 Word/PDF。

### 3.5 批改类

只迁移流程经验，不迁移当前主判断实现。

保留经验：

- OCR 和学生作答识别必须与标准答案分离。
- 有答案键时优先使用答案键。
- 无答案键时先生成参考答案，再标记低置信。
- 低置信不入档、不对外发布。
- 老师确认后才进入学生档案。

暂不迁移：

- 当前图片批改完整自动链路。
- 当前多模型批改审查链。
- 当前自动归档逻辑。
- 当前复杂坐标标注和 PDF 清单对齐。

新项目首期建议：

- 飞书上传图片后，机器人只做“识别与待复核摘要”。
- 若老师提供答案键，再做辅助批改草稿。
- 输出必须带置信度和“需老师确认”。

## 4. 新项目首期能力边界

建议首期只做 5 个命令：

- `/问答`：教学问答和讲解思路。
- `/资料`：资料入库、搜索、摘要。
- `/生成`：生成 Markdown 草稿。
- `/批改`：识别作答和辅助批改草稿。
- `/档案`：生成学生档案草稿。

首期不做：

- 微信小程序。
- 学生端登录。
- 家长端展示。
- 课堂平板和公共屏。
- 自动正式 PDF。
- 自动最终批改归档。
- 大量模型审查链。

## 6. 从旧项目可参考的文件

优先参考：

- `packages/ai/src/runtime.js`：模型调用、提示词边界、能力状态。
- `packages/services/src/index.js`：服务层封装、结构化输入输出、教师复核思想。
- `scripts/convert-to-markdown.mjs`：资料转 Markdown。
- `scripts/build-content-index.mjs`：内容索引。
- `docs/04-integrations.md`：飞书集成方向。
- `docs/41-prompt-context-engineering-playbook.md`：上下文与提示词工程经验。
- `docs/49-codex-plugin-usage-boundary-and-optimization.md`：限制插件介入范围的经验。

谨慎参考：

- `apps/api/src/server.js`：当前接口集中度过高，只参考路由设计，不直接复制。
- `apps/miniprogram/**`：小程序暂停，不迁移。
- `scripts/generate-assessment-fixtures.mjs`：仅参考 fixture 思想，不直接迁移生成内容。
- `scripts/inspect-generated-pdfs.py`、`scripts/render-pdf-pages.py`：首期不做 PDF 主流程。

## 7. 迁移执行顺序

1. 新建干净仓库，不从当前脏工作区直接复制全量代码。
2. 先搭建飞书机器人收消息、回消息、命令解析。
3. 接入 AI 问答和资料摘要。
4. 接入资料 Markdown 化和轻量索引。
5. 接入生成 Markdown 草稿。
6. 接入批改的 OCR/答案键辅助草稿，但默认不归档。
7. 接入学生档案草稿。
8. 稳定后再考虑文件导出、PDF、数据库和管理后台。

## 8. 当前仓库处理建议

当前仓库不要继续扩大改动。后续应单独安排一次清理：

- 按 `git status --short` 分组确认。
- 保留项目规则、服务层、AI runtime、资料工具、必要文档。
- 暂停小程序相关新增页面继续开发。
- 生成物、缓存、日志和临时文件按规则排除。
- 生成/批改相关未完成改动先不要继续叠加，等新项目边界确定后再决定是否保留。
