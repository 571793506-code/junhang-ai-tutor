# Web 与 iPad 局域网一致性设计

## 状态

- 日期：2026-07-13
- 状态：方案已确认，等待书面规范复核后进入实施计划
- 当前分支：`codex/fix-assessment-generation-layout`

## 背景

君航 AI 助教当前 Web 端已经具备桌面侧栏、`1100px` 与 `640px` 响应式断点、图片上传入口，以及 `dev:api:lan` / `dev:web:lan` 两个局域网启动命令。Chrome 对当前页面的实测结果如下：

- `1024 x 768` iPad 横屏：页面与 API 正常，无横向溢出，无控制台错误。
- `768 x 1024` iPad 竖屏：页面与 API 正常，无横向溢出，无控制台错误；主内容从约 `323px` 处开始，顶部身份与模块导航偏高。
- `390 x 844` 与 `430 x 932` 手机视口：页面可以打开且无横向溢出，但整页接近 `3900px`，部分控件低于 `44px`，不适合作为正式业务操作端。

现状已经达到“iPad 可以打开”，但还没有形成明确的 iPad 触控、Safari、横竖屏、拍照上传和真实局域网验收标准。

## 已确认决策

1. 采用同一套响应式 Web 应用，不新建 iPad 专属页面、路由或前端工程。
2. 电脑 Web 与 iPad 使用相同的 React 组件、API、权限、生成、复核和导出链路。
3. iPad 横屏和竖屏都完整支持，不隐藏教师端、学生端或课堂平板端的现有功能。
4. iPad Safari 为主要浏览器，iPad Chrome 兼容；桌面端继续以 Chrome 自动化验证为主。
5. iPad 可以调用相机或相册上传作业图片，并可选择多张图片；详细逐题复核与电脑 Web 一致。
6. 手机不作为业务操作端，不开发手机专属导航、页面或流程。
7. 手机窄屏仍可打开页面，只显示非阻断提示，建议改用 iPad 或电脑；不主动禁止访问或禁用操作。
8. 第一阶段只支持电脑与 iPad 位于同一 Wi-Fi 的局域网访问，不增加外网部署、HTTPS、PWA 或桌面安装能力。

## 目标

- 让 iPad 横屏和竖屏完整使用现有 Web 教学工作流。
- 保证电脑与 iPad 不出现两套业务实现、状态或权限判断。
- 让关键按钮、表单、身份切换和模块导航满足触控操作要求。
- 让 iPad Safari 可以登录、切换模块、生成草稿、打开 PDF、拍照或选图上传、逐题复核和确认。
- 复用现有局域网启动命令，让同一 Wi-Fi 下的 iPad 使用电脑局域网 IP 访问 Web 与 API。
- 对手机保持可访问但不承诺业务适配，并明确推荐设备。

## 非目标

- 不开发原生 iOS 或 iPadOS 应用。
- 不创建 iPad 专属业务组件树或复制现有 Web 页面。
- 不开发手机教师端、手机学生端、手机底部导航或手机专属拍照流程。
- 不阻止手机打开页面，也不根据 User-Agent 强制退出。
- 不增加 PWA、离线缓存、推送通知、桌面图标或全屏安装。
- 不增加公网域名、HTTPS、反向代理、云部署或远程访问。
- 不修改生成、批改、学生档案、AI 问答和教材资料的服务层规则。
- 不通过本轮响应式改造扩大未复核内容的可见范围。

## 总体架构

保持单一数据流：

```text
电脑 Chrome / iPad Safari / iPad Chrome
                  |
                  | http://<LAN_IP>:5173
                  v
           同一套 React Web 应用
                  |
                  | VITE_API_BASE_URL=http://<LAN_IP>:8787
                  v
              现有 API 服务
                  |
                  v
     服务层、数据库、模型和教师复核门禁
```

响应式层只决定信息如何排布，不决定业务是否允许执行。所有角色可见性、模型输出处理、草稿确认、正式导出和归档门禁继续由现有 API 与服务层负责。

## 设备与断点策略

### 电脑 Web：大于 `1100px`

- 保持现有左侧固定导航和主工作区布局。
- 不因 iPad 适配重排桌面信息架构。
- 现有生成、批改和学生档案工作台继续使用桌面密度。

### iPad：`641px` 至 `1100px`

- 使用同一组件树和完整模块列表。
- 侧栏转换为顶部响应式导航区，但不使用手机抽屉或隐藏模块。
- 横屏优先保留合理的双列信息；只有复杂工作台在空间不足时转为单列。
- 竖屏允许内容区单列堆叠，但所有生成、上传、复核、确认和导出操作仍可到达。
- 身份切换、模块导航、按钮、输入框、选择器和文件入口的可触控高度不低于 `44px`。
- 不依赖 hover 才能发现或执行操作；触控设备的 hover 样式不能成为唯一状态提示。
- 使用 `100dvh` 和 `env(safe-area-inset-*)` 处理 Safari 动态地址栏和安全区，保留 `100vh` 兼容回退。
- 横竖屏切换后通过 CSS 自适应，不刷新路由、不丢失当前身份或表单状态。

### 手机窄屏：不大于 `640px`

- 页面继续渲染，不做访问拦截。
- 在主内容顶部展示一次持续可见但不遮挡操作的提示：`当前页面以 iPad 或电脑为完整使用设备，手机仅供临时查看。`
- 不创建手机底部导航、抽屉导航或独立模块路由。
- 不把手机视口纳入完整业务流程通过条件，只检查页面可打开、提示可见、没有框架错误和严重横向溢出。

断点按 CSS 视口宽度处理，不使用设备品牌或 User-Agent 判断。这样 iPad 分屏和不同尺寸机型仍能按真实可用空间布局。

## Web 外壳与导航

### 单一组件树

`apps/web/src/main.tsx` 继续只渲染一套 `app-shell`、角色切换、模块导航和主工作区。iPad 不引入 `isIPad` 条件分支，也不复制教师、学生或课堂平板页面。

### iPad 导航

- 保留品牌、教师端/学生端/课堂平板身份切换和当前角色的完整模块导航。
- iPad 横屏将品牌与身份切换压缩在同一顶部区域，模块导航使用紧凑网格，减少进入主内容前的高度。
- iPad 竖屏允许导航增加行数，但每个入口保持完整文字、图标和至少 `44px` 高度。
- 模块切换继续复用现有 `activeModule` 状态，不新增 URL 路由或服务端状态。
- 键盘焦点和 `aria` 状态继续可用，触控优化不能破坏桌面键盘操作。

### 内容布局

- 复用现有 `minmax(0, 1fr)`、`min-width: 0` 和断点规则，禁止用固定宽度制造横向滚动。
- 表单在 iPad 横屏可使用两列，在竖屏按可用宽度收敛为一列。
- 生成、批改、资料和档案等复杂模块保持完整字段；可改变排列顺序，不删除步骤。
- PDF 审查链接、布局风险提示、正式导出门禁和教师确认按钮必须在横竖屏均可访问。
- 页面区段不使用嵌套横向滚动作为主要导航方式。

## 触控与 Safari 适配

### 触控目标

- 主要按钮、次要按钮、导航按钮、身份切换、输入框和选择器的最小高度为 `44px`。
- 图标按钮保持稳定的正方形触控区域，并保留可访问名称。
- 控件之间保留足够间距，避免教师在复核和正式导出时误触相邻危险操作。
- 可点击元素使用 `touch-action: manipulation`，不通过禁用缩放来优化点击。

### 表单和输入

- 输入框、选择器和文本域字体不低于 `16px`，避免 iPad Safari 聚焦时自动放大页面。
- 不修改现有字段含义、请求结构或前端校验边界。
- 表单聚焦后允许 Safari 正常滚动到输入位置，避免固定容器形成滚动陷阱。

### 拍照与相册上传

- 继续使用原生文件输入，`accept="image/*"` 作为图片来源约束。
- 需要现场拍照的入口保留 `capture="environment"` 作为后置摄像头提示，但不假设 Safari 一定直接打开相机。
- 保留 `multiple`，允许 iPad 从相册选择多张图片；相机拍照与多选能力以实际 Safari 提供的来源菜单为准。
- 上传后继续使用现有 API、进度、失败摘要和教师复核流程，不在 iPad 前端新增图片识别或评分逻辑。
- 文件选择取消、权限拒绝、格式不支持、网络中断和上传失败都留在当前页面显示可恢复状态，不清空已经选择成功的其他图片。

### PDF 与新标签页

- 草稿和正式 PDF 继续由 API 生成，iPad 只打开服务端资产 URL。
- Safari/Chrome 新标签打开失败时，链接仍保持为普通可点击地址，不改为前端拼接或内嵌原始 PDF 数据。
- PDF 审查、布局校验和正式导出资格继续以服务端状态为准。

## 手机提示

新增一个纯展示组件，例如 `MobileUseNotice`：

- 在 React 组件树中始终存在，通过 `@media (max-width: 640px)` 控制显示。
- 使用 `role="note"`，不使用模态框、全屏遮罩或必须确认的弹窗。
- 不读取 User-Agent，不写入 localStorage，不跟踪设备。
- 不隐藏任何现有内容，不禁用按钮，不修改权限。
- 文案只说明推荐设备，不宣称手机功能故障。

## 局域网运行

复用现有命令：

```powershell
cmd /c npm.cmd run dev:api:lan
cmd /c npm.cmd run dev:web:lan
```

运行约束：

- API 使用 `API_HOST=0.0.0.0` 监听 `8787`。
- Web 使用 Vite `--host 0.0.0.0` 监听 `5173`。
- Web 启动时把 `VITE_API_BASE_URL` 设置为 `http://<LAN_IP>:8787`。
- iPad 只能打开脚本输出的 `http://<LAN_IP>:5173/`，不能使用 `127.0.0.1`。
- 电脑与 iPad 必须位于同一 Wi-Fi 和可互访网段。
- Windows 防火墙放行由用户在系统提示中确认；脚本不自动修改防火墙规则。
- IP 变化后重新运行局域网脚本，不把局域网 IP 写死到源码或 Git。

局域网启动失败时必须区分：IP 检测失败、端口被占用、API 未监听、Web 未监听、防火墙阻断和设备不在同一网段，不能只返回“无法访问”。

## 可见性与安全边界

- 局域网适配不改变教师端、学生端和课堂平板端权限。
- 学生和家长仍不得看到供应商、模型、路由、内部 prompt、调试字段或未复核内容。
- 生成和批改仍是教师草稿；正式导出、归档和发布仍执行现有教师确认门禁。
- 第一阶段局域网 HTTP 只用于受控同 Wi-Fi 教学现场，不用于公共网络或互联网暴露。
- 不在浏览器中保存新的密钥、数据库连接或模型配置。

## 错误与降级

- API 不可达：显示现有同步失败状态，保留页面结构和重新尝试入口。
- 局域网 IP 检测失败：启动脚本停止并提示显式设置 `LAN_IP`，不退回 `127.0.0.1` 误导 iPad。
- 相机权限拒绝：允许用户返回文件选择器改用相册或文件。
- 文件选择取消：不触发上传，不显示系统级错误。
- 上传中断：显示当前步骤和可重试状态，不把未完成结果写入批改或档案。
- Safari 不支持某个非关键视觉效果：降级为普通背景或静态状态，不影响操作和可读性。
- 手机访问：只显示推荐设备提示，不拦截、不自动跳转。

## 测试策略

### 静态与单元守卫

扩展现有 `scripts/web-responsive-ui-regression.test.mjs`，至少检查：

- iPad 断点仍保留完整导航和工作台布局规则。
- 触控设备的主要控件达到 `44px` 最小高度。
- Safari 安全区和动态视口规则存在。
- 手机提示组件存在且只在窄屏显示。
- 手机提示不包含阻断、禁用或跳转逻辑。

保留并运行 `scripts/web-lan-access.test.mjs`，确认局域网脚本、API host 和 Web host 契约未漂移。

### Chrome 自动化视口

使用 Chrome 对同一 URL 检查：

| 视口 | 目标 |
| --- | --- |
| `1440 x 900` | 桌面侧栏与现有工作流无回归 |
| `1024 x 768` | iPad 横屏完整导航、表单和工作台 |
| `768 x 1024` | iPad 竖屏完整导航与单列工作流 |
| `390 x 844` | 手机提示可见、页面可打开、无严重横向溢出 |

每个视口至少检查：页面标题、非空内容、无框架错误覆盖层、控制台错误、`scrollWidth <= innerWidth`、关键控件可见和一次模块切换。iPad 视口还需检查身份切换、生成打印、批改复核和文件输入可到达。

### 真实 iPad Safari 验收

Windows Chrome 视口不能证明 Safari 已通过。发布前必须在同一 Wi-Fi 的真实 iPad Safari 完成：

1. 使用脚本输出的局域网 Web URL 打开页面。
2. 完成教师登录并确认 API 状态。
3. 横屏和竖屏各切换一次，确认当前身份和表单状态不丢失。
4. 进入生成打印，检查配置、草稿 PDF、布局风险和正式导出门禁。
5. 进入拍照批改，分别验证相机拍摄一张、相册选择多张、取消选择和上传失败提示。
6. 打开 PDF 草稿并返回工作台，确认页面状态可继续操作。
7. 完成逐题复核的查看与一次非正式状态修改；正式确认仍按测试数据边界执行。
8. 检查无横向溢出、无输入自动放大、无固定区域遮挡、无滚动陷阱。

### iPad Chrome 兼容验收

在同一 iPad Chrome 重复登录、横竖屏、模块切换、图片选择和 PDF 打开五项核心检查。Safari 为主要准入结果，Chrome 的浏览器特有差异单独记录。

### 项目验证命令

```powershell
node --test scripts/web-responsive-ui-regression.test.mjs
node --test scripts/web-lan-access.test.mjs
npm.cmd run typecheck --workspace apps/web
.\jh.cmd check:api
.\jh.cmd check:encoding
git diff --check
```

涉及真实局域网运行时，再启动 `dev:api:lan` 和 `dev:web:lan`，并从 iPad 执行人工验收。普通单元测试不得自动修改防火墙或依赖真实 iPad 在线。

## 计划修改范围

- `apps/web/src/main.tsx`：增加非阻断手机提示，并确保现有文件输入和完整工作流可在 iPad 到达。
- `apps/web/src/styles.css`：收敛电脑/iPad/手机断点，增加触控尺寸、安全区、动态视口和 iPad 横竖屏布局。
- `scripts/web-responsive-ui-regression.test.mjs`：增加 iPad、触控、Safari CSS 和手机提示守卫。
- `scripts/web-lan-access.test.mjs`：仅在发现现有局域网契约缺口时补充定向测试。
- `scripts/dev-web-lan.cmd` / `scripts/dev-api-lan.cmd`：只在真实启动验证发现 IP、监听或诊断缺口时做最小修复。
- `docs/23-local-run-smoothness.md`：把“iPad / 手机展示”更新为“iPad 完整支持、手机临时查看”的实际边界和真机验收步骤。

不修改 API 业务路由、服务层、数据库、小程序页面或模型调用。

## 实施顺序

1. 先用静态测试固定 iPad 断点、触控目标、安全区和手机非阻断提示契约。
2. 最小修改 Web 外壳和样式，使测试通过。
3. 在 Chrome 完成桌面、iPad 横屏、iPad 竖屏和手机查看态的响应式回归。
4. 验证现有局域网脚本；只有真实证据显示缺口时才修复脚本。
5. 更新本地运行手册和真实 iPad Safari/Chrome 验收清单。
6. 在真实 iPad Safari 完成主验收，在 iPad Chrome 完成兼容验收。

## 成功标准

- 电脑和 iPad 运行同一套 Web 代码、API 和业务规则。
- iPad 横屏与竖屏均可访问全部现有模块和关键操作。
- iPad 主要交互控件不低于 `44px`，输入聚焦不触发 Safari 自动放大。
- iPad 可拍照或从相册多选图片，上传继续进入现有批改与教师复核链路。
- Chrome 四个目标视口没有严重横向溢出、框架错误或控制台错误。
- 真实 iPad Safari 完成局域网、横竖屏、上传、PDF 和复核验收；iPad Chrome 完成兼容检查。
- 手机仍可打开页面并看到推荐设备提示，但没有新增手机专属业务实现。
- 局域网 IP 不写入源码，防火墙不被脚本自动修改。
- 桌面 Web、API 权限、多端可见性和教师复核门禁没有回归。
