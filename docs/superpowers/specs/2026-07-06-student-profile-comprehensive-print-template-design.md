# 学生成长档案综合打印模板设计

日期：2026-07-06

## 背景

学生档案长期成长档案已确定采用周档案、月度综合档案、期中综合报告和期末综合总结的组合。由于当前小程序尚未正式投入使用，周/月档案也需要支持教师端生成打印版或 PDF，方便老师审查后人工发给家长。

本次修订明确：君航项目暂不采用飞书项目里的“单科模板 + 综合模板”双路径。三科内容只作为综合成长档案内部板块出现，不提供单科独立模板入口。

## 目标

- 所有学生成长档案都使用综合模板体系。
- 周档案、月度档案、期中报告、期末总结属于同一套综合成长档案家族。
- 周/月档案增加打印版正文结构，内容深度向期中/期末靠拢，但篇幅更短。
- 周/月打印版必须由结构化数据和 HTML/PDF 模板渲染正文，不使用 image 2 图片文字作为正式正文。
- 教师端可先生成草稿、审查内容、保存打印版；当前可人工微信发送，后续可发布到学生端。

## 非目标

- 不做单科独立模板。
- 不按语文、数学、英语分别生成三份报告。
- 不做成绩排名、预测分、班级位置或冲刺战报。
- 不接入微信自动发送。
- 不把教师复核证据包、低置信来源、模型、供应商、prompt、debug 字段放入学生/家长可见正文。

## 模板家族

### 周综合成长档案

建议 1 到 2 页。定位是轻量但完整的本周反馈，重点回答：

- 本周整体状态是什么。
- 三科分别有什么可观察记录。
- 本周最需要跟进的方向是什么。
- 错题订正做到哪一步。
- 下周老师优先做什么。
- 家长在家可以观察或配合什么。

模块：

- 档案信息与教师确认状态。
- 本周综合成长摘要。
- 三科总览。
- 本周重点方向展开，最多 1 个。
- 错题与订正闭环。
- 稳定表现。
- 下周辅导重点。
- 家长下一步。

### 月度综合成长档案

建议 2 到 4 页。定位是长期成长档案的核心形态，重点回答：

- 本月整体学习节奏和变化是什么。
- 哪些表现比较稳定。
- 哪些薄弱点重复出现。
- 三科能力点分别如何观察。
- 下月老师如何安排，家庭如何短时配合。

模块：

- 档案信息与月度综合摘要。
- 证据覆盖摘要。
- 三科总览。
- 学科能力拆解。
- 重点方向展开，最多 1 到 2 个。
- 共性错因分析。
- 课堂与作业过程。
- 稳定表现。
- 下月辅导计划。
- 家校协同建议。
- 家长沟通摘要。

### 期中综合成长报告

继续走教师端 PDF。内容深度高于月档案，强调阶段掌握、共性错因和接下来两到四周安排。

### 期末综合成长总结

继续走教师端 PDF。内容深度最高，强调学期成长、稳定强项、假期或下阶段安排。

## 数据契约

周/月 snapshot 增加 `printView`，与现有 `publishedView` 并列：

- `printView.templateType` 固定为 `comprehensive_growth_archive`。
- `printView.periodType` 为 `weekly` 或 `monthly`。
- `printView.title` 为 `周综合成长档案` 或 `月度综合成长档案`。
- `printView.pageHint` 为建议页数。
- `printView.renderingPolicy.pdfTextSource` 固定为 `html_template`。
- `printView.renderingPolicy.imagePreviewUsage` 固定为 `visual_reference_only`。
- `printView.sections` 保存打印正文模块。

`printView.sections` 使用综合模板，不包含单科模板标识。三科内容仅出现在 `subjectOverview` 和 `subjectAbilityMap` 中。

## 可见性

- 教师端 draft 可见 `printView`、`teacherReview` 和 `profileEvidencePack`。
- 学生/家长端发布视图可见 `publishedView` 和经教师确认后的公开内容。
- 学生/家长端不接收 `teacherReview`、`profileEvidencePack`、原始证据包、模型供应商、prompt、debug、raw。
- 周/月打印正文用于教师审查后打印、保存或人工发送；未来如发布到学生端，仍必须经过教师确认。

## 实现边界

第一步先在服务层生成 `printView` 和 HTML 渲染函数，现有 profile draft/publish/profile snapshot 会自动携带结构化模板。后续教师端 UI 可以直接基于 `printView` 做打印预览、下载和状态记录。

本次实现不新增单科模板、不新增数据库表、不改期中/期末现有 PDF 状态机。
