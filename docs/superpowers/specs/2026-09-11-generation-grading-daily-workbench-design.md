# 生成与批改日常工作台设计

**日期：** 2026-09-11

**状态：** 用户已认可模型职责及“对话提出要求＋结构化成果直接编辑”的交互方向；本文固化设计与工程建议，功能尚未实施。

**实施计划：** [分阶段计划](../plans/2026-09-11-generation-grading-daily-workbench.md)

## 1. 目标与本轮边界

首要目标是生成与批改满足教师日常教学需求，并让项目对话与 Web 可以继续同一项工作。质量、教师修改量和任务完成时间共同决定可用性；进入待复核状态不等于质量达标。

- 本轮聚焦生成、批改、所需资料上下文、模型路由、Skills、任务版本和两个教师工作台。
- 本轮不推进小程序、课堂屏、独立资源库重建、学生档案重建或全站视觉重做。
- 继续复用现有资料检索、档案归档、身份权限和打印能力。
- 同一任务指相同身份范围、原始要求、资料版本、内容版本、教学规则及确认记录，不要求随机生成逐字相同。
- 本设计确定目标行为，不代表当前网关已经支持目标模型、图像或所有请求参数。

## 3. 已确定的模型职责

| 工作 | 首版职责 | 限制 |
| --- | --- | --- |
| 核心生成、教学设计、完整解析 | Astra | 先建立质量基线，不默认安排其他模型再写一遍 |
| 主观题、过程题、合理异解判断 | Astra | 按题组提供必要证据；总分不能由模型覆盖 |
| 需求提取、资料片段整理 | Flash，按需 | 原始教师要求与来源片段继续保留，摘要不是唯一上下文 |
| 作答识别 | Flash 候选适配器，与现有 OCR 对照 | 首版不自动撤掉已用 MiniMax 路线；通过真实图片比较后切换 |
| 确认反馈的语言简化等独立任务 | Sol 可选 | 不修改分数、答案、评分点或教师结论；不作为每次必经环节 |
| Astra 暂时不可用 | Sol 受控接替未完成单元 | 仅 availability；共享剩余预算；接替失败即结束 |
| 题量、分值、来源指纹、明确客观题 | 服务层 | 保守判定，不把开放题简单字符串比较 |
| 发布、正式导出、归档 | 教师确认后由服务层执行 | 模型不能授权、确认或伪造教师身份 |

目标 API 名称为 `gpt-6-astra`、`gpt-5.6-sol`、`deepseek-flash`，由独立配置映射，不把 Codex App 可选模型等同于项目网关已授权模型。Astra 不使用 `none`；核心生成和主观批改以 `high` 作为首轮基线候选，是否调整档位由实测决定。

官方资料已在本次讨论中于 2026-09-11 查阅：

- [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)
- [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)
- [OpenAI 模型选型](https://developers.openai.com/api/docs/guides/model-selection)
- [DeepSeek V4.1 Flash 能力和价格](https://api-docs.deepseek.com/quick_start/pricing)
- [DeepSeek 视觉说明](https://api-docs.deepseek.com/guides/vision)

这些资料不证明本项目学生手写识别准确率、任务耗时或网关实际价格。DeepSeek 图片会缩放，密集手写内容需要按题裁剪；不能仅凭模型自报 confidence 选择最可靠识别。

## 4. Skills 与运行规则

保留三层职责，禁止独立维护两套教学规范：

1. `.agents/skills/generation/SKILL.md` 与 grading 入口负责发现、路由、工具调用方法和继续已有任务。
2. `skills/<module>/SKILLS.md` 负责执行流程、输入输出、证据优先级、教师操作及验证入口。
3. `skills/<module>/references/runtime-rules.md` 保存会实际进入模型的教学细则。模块 Playbook 引用该文件；运行时从服务端固定白名单加载，计算内容哈希，按任务选择片段。

模型策略的权威来源是 `packages/ai/src/model-policy.js`。Playbook 引用其任务职责，不再复制多份可漂移的超时与 token 数值。服务层继续负责不可由提示词替代的规则。

规则加载器不解释任意 skill、不执行 Markdown 内的命令、不接受客户端路径。资料文本与任务规则分开标记；资料内容不能修改身份、工具权限、模型路由或教师确认边界。读取失败时在模型调用前返回明确的规则配置错误，不悄悄使用旧提示词。

每个任务内部保存规则哈希、策略版本、资料来源版本和结构化校验问题；教师界面显示教学条件和可处理问题，不展示完整 prompt、密钥、供应商配置或 raw。

## 5. 生成流程

`kind` 继续表示小测、练习、试卷等交付类型；新增 `purpose` 区分 `comprehensive`、`focused`、`multi_day`、`explanation`。错题复练属于 focused，并附带已确认错题来源。字段为本设计新增目标，现有调用缺省 comprehensive 保持兼容。

流程：保留要求 → 核对必要条件 → 按需资料提取 → 形成蓝图并生成 → 程序检查 → 有限局部修订 → 教师确认 → 导出。

- 要求完整时直接执行；关键范围缺失或冲突时才追问。纯专项不依赖无关教材资产；明确声明教材时继续要求真实同版本已审批资料。
- focused 不强制混入综合题型。multi_day 明确各日目标、题量与递进关系；explanation 产出讲解与例题，不能被误写成试卷。
- 简单任务一次内容调用；长任务按题组或天数生成，共享蓝图。阅读材料与相关题目在同一教学单元中处理，避免逐小题切断上下文。
- 题干、标准答案、解析步骤、知识点、评分点、图形与作答空间组成同一份结构化成果。
- 程序检查 schema、题量、重复、分值、答案包完整性及可确定的算术，不把“校验通过”包装成所有学科答案已正确。
- 只有明确 quality 问题允许原责任模型局部修复一次；availability 可改用 Sol 一次。两者共享同一个追加调用名额，不形成 Astra 重试后再 Sol 的无限链。
- 教师修改第 3 题时仅重新计算其答案、解析及依赖。修改阅读材料影响整题组；修改第五天不重写前四天。
- 内容可编辑后即可进入工作台；预览导出单独执行。正式学生卷、解析卷与答案包绑定确认版本，预览失败不能删除内容。
- 低预算测试兜底只标记演示/链路测试结果，不混入正式质量基线。

## 6. 批改流程

流程：验证作业与来源 → 识别题干和作答 → 检查证据 → 客观题程序处理、未解决题组交给 Astra → 汇总 → 教师修正和确认 → 归档。

- 生成材料优先使用有效 `gradingSourcePackage`、来源版本和布局清单；外部材料使用教师参考答案或标为模型推导的参考答案。
- 识别记录分别保存 printedPrompt、studentAnswer、observedWork、页序、区域、原图引用及疑点；不以印刷题干补学生答案。
- 只识别不清时补裁剪/重识别，不升级文本推理。关键内容确实缺失时保留疑点，禁止虚构。
- 主观判断输入含原始证据、评分依据与教师修正。过程题和疑难题支持访问对应裁剪图，文本提取不是唯一证据。
- 模型推导参考答案不是教师答案；同一模型随后认可自己的参考答案不构成独立验证。
- 逐题输出 questionId、questionNo、status、score、maxScore、评分点、扣分依据、错误步骤、建议及 evidenceRefs。无法评分时 score 为 null，不能用 0 伪装识别失败。
- 总分仅由完整、有效的逐题分数计算。置信度、识别质量、评分争议、确认状态为不同字段。
- 教师修正识别后只重批相关题；修改共享参考答案/评分点时扩大到相关题组。已归档记录保持原快照，修订形成新版本及替代关系，档案聚合不得重复计入。

## 7. 持续任务、版本与确认

新增两个持久化对象，名称分别为 `TeachingWorkflow` 和 `TeachingWorkflowRevision`，不建立通用 agent 平台。

- TeachingWorkflow：id、ownerTeacherId、module、subjectRef、requestKey、currentRevision、status、request、checkpoint、createdAt、updatedAt。module 仅 generation/grading；subjectRef 关联既有 assignmentId 或 submissionId。request 和 checkpoint 只保存服务端校验后的数据与文件引用。
- TeachingWorkflowRevision：workflowId、revision、baseRevision、operationKey、operation、actorTeacherId、snapshot、createdAt。以 `(workflowId, revision)` 和 `(workflowId, operationKey)` 唯一约束防并发覆盖与重复提交。
- 创建任务的 `(ownerTeacherId, requestKey)` 唯一约束保证同一次重发不创建重复任务。requestKey 相同而请求内容不同返回冲突。
- snapshot 保存规范化内容、稳定题目 ID、来源指纹、逐题确认和摘要；图片/PDF 使用已有资产引用，不复制二进制或原始模型响应。
- 更新事务以 expectedRevision 比较当前版本；过期提交返回 409 `WORKFLOW_VERSION_CONFLICT`，不静默覆盖另一入口的修改。
- 用户可见历史版本不可原地改写。恢复旧版也生成新版本；以前的导出与归档保持原绑定。
- 确认凭据包含服务端确认人、时间、内容指纹、证据指纹和评分规则版本。展示排版变化不自动否定内容确认；题干、答案、分值、来源证据变化使相关确认失效。
- 对话 JSON 自带 confirmedBy/confirmedAt 不足以可信。通过已认证项目入口完成确认，或匹配已有服务端可核验归档，才复用凭据；普通未验证导入保持待确认。

任务状态：`queued → running → ready_for_review → confirmed`；还允许 `needs_input`、`interrupted`、`failed`、`cancelled`。归档和导出是绑定版本的操作，不合并为一个含糊的终态。

验证通过的部分内容及时写入 checkpoint。服务重启把遗留 running 标为 interrupted，允许用户明确继续；不在启动时自动重新收费。取消和迟到模型响应不能覆盖已取消或更新后的版本。首版采用单 API worker，数据库保证版本事务；不扩展分布式队列。

## 8. 两个入口与 UI

两个入口共享服务与权限，Codex 使用薄 CLI `scripts/teaching-workflow.mjs` 调用 API，不直接绕过 API 写数据库。教师会话通过受保护的本地会话文件读取，不放在命令行、日志或成果中。CLI 输出教师安全 JSON，支持创建、查看、修订、确认和继续任务。

生成工作台：

- 对话区表达任务与修改意图；条件区展示年级、目标、范围、题型和来源，可直接编辑。
- 成果区按题、题组或天数编辑；学生版/解析版切换、选中后局部修改、版本比较与恢复。
- 数量少的明确操作无需对话：上传、选择年级、直接改文字、确认、导出。

批改工作台：

- 左侧批次/题目导航；主体原图和当前题结果对照；疑点优先但整份仍可查看。
- 识别文字、评分点、得分可直接修正；对话用于异解说明或重判指定题。
- 可以明确选择已检查题目批量确认，服务端逐题登记，不允许“全部确认”跳过未读/无法评分/证据缺失题。
- 归档前展示剩余问题，已经核验的确认不反复要求。

延用现有站点导航和视觉基础。只提取两个相关模块组件，不重构全站 main.tsx。窄屏改成分区切换，保留当前题目和未保存编辑；本轮不构建小程序。

## 9. 调用预算与可用性

- 首版继承现有生成场景总预算上限，作为工程起点而非用户认可的速度标准；多日大任务通过持久化单元明确分批，不能隐式无限延长总预算。
- 每个内容单元一次主调用、最多一次修复或替补；长任务最多两路并发并共享取消信号及剩余总预算。
- Flash 辅助调用按必要步骤执行，消耗同一任务预算；没有提取需求时调用数为 0。
- 不因 configuration、evidence 或教学争议切换 Sol；不把供应商过载和余额不足混为同一种 429。
- 在切换路由前做合成输入的文本/JSON/视觉能力探针。运行时失败返回清楚可恢复状态，不以启动配置存在代替实际能力。
- 第一阶段不新增任意第三模型接力、自动多模型投票或隐藏后台质量调用。

## 10. 验收口径

工程不变量必须全部通过：

1. 相同任务可从对话 CLI 创建、在 Web 修改，反向亦然。
2. 局部修改不改变无关题目的内容指纹和有效确认。
3. 并发旧版本、跨教师访问、伪造确认和取消后的迟到结果均被拦截。
4. 重启保留已完成单元，不自动重新调用模型；续作不重复归档。
5. 分数由逐题汇总；不确定题不能伪装为 0 分；学生版无答案泄漏。
6. 内容、答案包、学生卷和解析卷版本一致；正式导出必须确认。
7. Web 和 CLI 不包含内部模型配置、raw、prompt 或密钥。

真实教学验收分别覆盖专项计算、英语字母/句型、综合试卷、多日训练、清晰作业、过程题及模糊照片。生成比较要求遵循、正确性、解析、排版和教师修改量；批改比较识别、逐题评分、异解、公示反馈与教师修改时间。

已有教师确认金标可以复用，调试样本与留出样本分开。教师确认是业务依据，不等同于所有历史标签永不出错；有争议的金标注明并重新复核，不能为了让模型通过而偷偷改标签。

不得仅凭合成测试、可归档、模型自评分或旧回放声明生产可用。具体可接受时长、成本和修改量仍需真实任务后与教师确定；报告必须明确样本范围、未通过项及人工结论。

## 11. 完成与下一动作

设计和计划文档完成不等于软件完成。下一工程动作是实施计划阶段一：先让共享教学规则与任务模型策略可执行、可测试，再增加持久化修订与 UI。真实费用调用与默认路线切换须在能力与样本证据具备后执行，不由本设计文档直接触发。
