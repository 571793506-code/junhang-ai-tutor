# 学生端共享英语词典设计

## 状态与目标

本设计于 2026-07-16 经用户确认，替代 `2026-07-15-student-vocabulary-wordbook-design.md`。

学生端英语词汇模块改为共享英语词典查询，不再建设个人词汇本。学生输入任意英文单词或常见词形后，系统返回适合小学三至六年级理解的完整词条。查询结果不关联学生 ID，不形成个人词卡列表、收藏或查询历史。

成功标准：

- 任意合法英文单词可以通过真实 API 查询，不依赖页面静态词库。
- `carried`、`goes`、`better` 等常见变化形式能够定位原形，并解释当前词形与原形的关系。
- 完整词条至少覆盖音标、多词性释义、词形变化、近义词、例句、搭配和易错点。
- 已生成且校验通过的词条由所有学生共享复用，重复查询不再次调用模型。
- 模型调用失败、结构异常或词条与查询词不匹配时，不缓存、不展示空词条。

## 范围边界

本期包含：

- Web 学生端和微信小程序学生端的单词查询。
- 系统级共享词典缓存。
- 常见屈折变化和不规则变化的原形解析。
- 服务端生成、规范化、校验、缓存和学生可见字段过滤。
- 加载、无结果、生成失败和重试状态。

本期不包含：

- 个人词汇本、收藏、查询历史、个人笔记、编辑或删除词条。
- 教师词库管理、人工词条编辑、发音音频、听写或词汇测验。
- 外部商业词典 API 或词典版权数据导入。
- 根据单个学生档案改写共享词条。

## 方案选择

采用“共享词典缓存 + 缺词时 AI 生成并严格校验”。

未采用的方案：

- 每次查询实时调用 AI：实现较短，但响应慢、成本重复，且相同单词可能得到不一致结果。
- 首期接入外部商业词典：词源更权威，但需要先确认授权、费用、字段范围和服务稳定性。

共享缓存满足当前真实数据链路要求，也允许后续在不改变学生端契约的前提下，用已授权词典来源替换生成来源。

## 数据模型

新增全局 `DictionaryEntry`，不包含 `studentId`：

- `id`：词条 ID。
- `headword`：规范化后的原形，唯一。
- `card`：通过校验的 `student-dictionary-entry-v1` 共享词条主体，不包含随查询词变化的 `queryRelation`。
- `createdAt`、`updatedAt`：缓存创建和更新时间。

新增 `DictionaryAlias`：

- `term`：规范化后的可查询形式，唯一，例如 `carried`、`goes`、`better`。
- `entryId`：指向对应 `DictionaryEntry`。
- `relationType`：`headword`、`plural`、`third_person`、`past`、`past_participle`、`present_participle`、`comparative`、`superlative` 或 `irregular`。
- `relationLabel`：面向学生的中文关系说明。

原形本身也写入 `DictionaryAlias`，关系为 `headword`。查询先按 alias 精确命中，因此变化形式与不规则形式都复用同一份共享词条。

已创建的个人 `VocabularyEntry` 能力退出产品链路。实现阶段移除其页面、API、服务和仓储入口，并通过后续迁移移除尚未正式使用的个人词汇表。既有 `VocabularyRecord` 历史审计数据保持不变，但新词典查询不再写入个人查询记录。

## 词条契约

学生可见词条结构包含：

- `headword`：原形。
- `phonetic`：主音标。
- `queryRelation`：本次输入与原形的关系说明，由服务端根据命中的 `DictionaryAlias` 动态组装，不写入共享词条主体。
- `parts`：一个或多个词性，每个词性包含中文词性名称和分义项中文释义。
- `forms`：复数、第三人称单数、过去式、过去分词、现在分词、比较级和最高级等实际适用形式。
- `wordFamily`：常用派生词及中文解释。
- `synonyms`：近义词、中文含义及简短用法区别。
- `antonyms`：适用时返回反义词及中文含义。
- `collocations`：常用搭配及中文解释。
- `examples`：至少两个适龄英文例句，每句带中文翻译，并尽量覆盖主要词性或常用义项。
- `usageNotes`：常见用法说明。
- `pitfalls`：拼写、词形或近义词使用中的易错点。

数组字段允许在语义上确实不适用时为空，服务端不得为了凑字段生成错误的近义词、反义词或词形。`parts`、中文释义、主音标和至少两个双语例句必须完整。

响应不得包含供应商、模型名、内部 prompt、原始输出、模型运行 ID、缓存主键或调试信息。

## API 与数据链路

新增学生会话接口：

```text
POST /api/student/dictionary/query
{ "word": "carried" }
```

服务端从已认证学生会话确认角色，但共享词条不保存学生身份。处理流程为：

1. 去除首尾空白、转为小写并校验英文单词格式。
2. 按 `DictionaryAlias.term` 查询共享缓存。
3. 命中时返回词条和本次词形关系，不调用模型。
4. 未命中时调用现有词汇生成能力，输入只包含查询词和三至六年级通用教学边界。
5. 解析并规范化严格 JSON，校验原形、查询词关系、必要字段、双语例句、乱码和内部字段。
6. 在同一事务中 upsert 原形词条及合法 aliases，再返回学生安全 DTO。

首次生成若发现模型返回的原形与查询词没有可解释关系，必须失败关闭。并发查询依赖原形和 alias 唯一约束收敛到同一词条，不创建学生级副本。

既有 `POST /api/ai/vocabulary` 不再作为学生端入口。Web 和小程序只调用新的共享词典接口，避免继续把失败的旧生成结果当作可展示词卡。

## 页面交互

模块标题改为“英语词典”，主按钮改为“查询单词”。页面不显示静态快捷词、个人列表、删除按钮或“保存到词汇本”文案。

一次只展示一个查询结果：

1. 顶部显示原形、音标和当前输入的词形关系。
2. 按词性展示分义项中文释义。
3. 展示词形变化和常用派生词。
4. 展示近义词、反义词及用法区别。
5. 展示常用搭配、双语例句、用法说明和易错点。

提交后保持输入框和结果区域尺寸稳定。加载时显示查询状态；失败时保留输入内容并显示可重试提示；只有完整词条才能进入结果区域。Web 和小程序复用同一响应契约，不在端侧补造静态内容。

## 错误处理

- 非英文输入：不调用模型，提示“请输入英文单词”。
- 空输入：不发送请求。
- 缓存读取失败：返回通用词典暂不可用提示。
- 模型不可用、超时或返回无效结构：不写入词条或 alias，返回“暂时无法完成查询，请稍后重试”。
- 已有缓存词条结构不符合当前 schema：不直接展示，由服务端重新生成；重新生成仍失败时返回通用错误。
- 所有学生端错误隐藏模型、供应商、数据库和内部校验细节。

## 测试与验证

实施采用测试先行，覆盖：

- 仓储：原形和 alias 唯一约束、按变化形式命中同一词条。
- 服务层：输入规范化、缓存命中零模型调用、缓存未命中生成一次、词形关系校验、无效结果不持久化。
- API：只接受学生会话、忽略客户端伪造身份、只返回白名单字段。
- Web：只调用查询接口，完整展示词条，不包含个人新增、列表或删除逻辑。
- 小程序：不引用静态 `dictionary`、个人词汇本接口或 fallback 词卡，具备完整查询状态。
- 回归：模型 `ERROR` 或 `available=false` 时不再渲染只有单词和空括号的卡片。
