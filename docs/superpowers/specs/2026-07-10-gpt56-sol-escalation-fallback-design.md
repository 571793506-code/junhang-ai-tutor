# GPT-5.6 Sol High 升级兜底设计

## 1. 目标与范围

本设计在现有 `gpt-5.6-terra` 生成与批改主链路上增加一次受控的 `gpt-5.6-sol + high` 模型升级，用于处理两类问题：

- `terra` 请求发生可通过换模型缓解的超时、限流、上游故障或无有效响应；
- `terra` 返回结果经过项目服务层解析、标准化、校验和确定性修复后，仍存在明确的内容质量或批改可信度问题。

目标是提高生成和批改的完成率与正确性，同时保持正常请求速度、项目内容约束、教师复核和多端可见性边界不变。

本次范围只包括小测、普通练习、个性化练习、正式试卷、外部材料参考答案和逐题批改。问答、词汇、今日任务、学生档案、视觉 OCR、语音、PDF 排版和自动归档不进入 Sol 自动升级范围。

## 2. 已确认决策

1. `terra` 继续作为唯一默认文本模型，保持现有推理档位：小测和练习使用 `medium`，正式试卷、参考答案、主批改和风险处理使用 `high`。
2. Sol 升级固定使用 `gpt-5.6-sol + high`，不能降级为 `medium`，也不能继续串行切换到其他文本模型。
3. 默认采用最小失败单元：生成只重做失败分区或题目，批改只重做争议题；只有 `terra` 完全没有可用结果时才整项重做。
4. 故障类和质量类使用不同触发规则，但共享同一个单次升级门禁。
5. Sol 使用独立兜底预算，不消耗 `terra` 正常路径的剩余时间；只有触发升级时才增加等待。
6. 每个失败单元最多调用一次 Sol。整项重做时，每个分区仍只允许一次 Sol 请求，最多 2 路并发。
7. Sol 仍只产出内部草稿，不能绕过本地校验、教师复核、正式导出和归档门禁。

## 3. 配置与能力门禁

新增配置：

```dotenv
GPT56_SOL_FALLBACK_ENABLED=false
GPT56_SOL_MODEL=gpt-5.6-sol
GPT56_SOL_FALLBACK_TIMEOUT_MS=180000
```

Sol 与 Terra 使用同一组 `GPT56_API_KEY` 和 `GPT56_BASE_URL`。`high` 和单次尝试限制是项目固定策略，不增加可随意放宽的配置项。

运行时启用 Sol 必须同时满足：

- `GPT56_SOL_FALLBACK_ENABLED=true`；
- `GPT56_REASONING_EFFORT_ENABLED=true`；
- Sol 能力探测通过普通文本、`json_object`、`reasoning_effort=high`、JSON Schema 和项目批改 JSON；
- 当前调用不需要 Sol 直接读取图片。

`.env.example` 默认关闭 Sol。项目本地 `.env` 只有在合成能力探测和真实质量样本通过后才开启。能力探测不得发送真实学生数据。

## 4. 触发分类器

服务层结合 HTTP 状态、结构化错误码和错误消息，把失败归一为 `availability`、`quality`、`evidence` 或 `configuration`，再决定是否允许 Sol。不能只按 HTTP 状态判断，因为中转可能同时使用 `429` 表示短时限流和账户额度耗尽。

### 4.1 故障类触发

以下失败允许当前失败单元直接切换到 Sol：

- `MODEL_TIMEOUT`；
- HTTP `408`、`500`、`502`、`503`、`504`、`524`；
- HTTP `429` 且错误码或消息明确表示短时限流、并发拥塞或临时容量不足；
- 网络中断、连接重置或上游在读取响应前断开；
- 返回空内容，或中转响应体本身无法读取或解析。

以下失败不允许切换：

- HTTP `401`、`403` 等密钥或权限错误；
- 余额、额度、账户状态或中转整体配置错误，包括以 `429` 返回的 `insufficient_quota` 或同类错误；
- 请求参数无效、上下文过长或模型名不存在；
- Sol 能力探测未通过或能力开关未开启。

不允许切换的故障直接进入现有内部错误处理和教师复核，不用另一个模型重复同一错误。

中转响应体可读取，但模型消息不是有效 JSON 或不满足项目结构时归入 `quality`，不能混入网络故障统计。

### 4.2 生成质量触发

Terra 输出必须先执行 `parse -> normalize -> validate -> repair -> local audit`。完成一次确定性修复后仍出现以下硬问题，才允许升级：

- 分区缺失、题量不足、总分不符或题型结构错误；
- 缺少答案、解析步骤、考点、易错点或必要图形元数据；
- 明显重复、同质化，或偏离教师要求、年级、学科和教材上下文；
- 小测、练习和试卷结构混用；
- 失败分区无法形成严格结构化结果。

Sol 输入使用原始 `generationContext`、确定性蓝图、当前失败单元和校验问题清单。不要把整份 Terra 错误输出作为新提示词主体，避免错误锚定。

### 4.3 批改质量触发

只有题干、学生作答和答案证据清晰时，以下题目才允许升级：

- `status=uncertain`；
- 单题置信度低于 `0.62`；
- 参考答案冲突或参考答案生成失败；
- 模型总分与逐题汇总不一致；
- 明确答案题与确定性比较结果冲突；
- 主观题评分与评分点明显不一致。

Sol 只接收被标记题目的题干、学生作答、标准答案或参考答案、评分点、分值和必要的结构化 OCR 证据。Sol 返回逐题结果后，服务层重新计算总分并再次执行低置信门禁。

### 4.4 输入证据不足不升级

以下情况归类为 `evidence`，直接进入教师复核，不调用 Sol：

- 图片模糊、漏页、严重倾斜或曝光异常；
- OCR 没有识别到学生作答；
- 题干、关键条件、图形或页序缺失；
- 印刷题干和学生作答无法可靠分离；
- 没有足够依据生成参考答案或评分点。

更强文本模型不能补回不存在的证据，因此不得用 Sol 包装不可靠结论。

## 5. 生成升级数据流

1. Terra 按现有蓝图和最多 2 路并发生成分区。
2. 服务层保留所有可用分区，并对每个失败分区记录失败类别和校验问题。
3. `availability` 或 `quality` 分类器允许升级时，只把失败分区发送给 `gpt-5.6-sol + high`。
4. Terra 完全没有可用分区时，Sol 按原场景蓝图重新执行整项分区生成；仍保持最多 2 路并发。
5. Sol 结果重新经过 parse、normalize、validate、repair 和本地审查，再与已通过的 Terra 分区合并。
6. Sol 失败或仍不合格时，使用现有动态兜底补齐草稿并设置 `usedDynamicFallback=true`、`needs_teacher_review`。
7. Sol 成功且没有使用本地动态题池时，记录 `usedModelEscalation=true`，但不能错误标记为 `usedDynamicFallback=true`。

Sol 是 Terra 之后的终止模型升级。DeepSeek V4 Flash 继续保留为运维显式紧急回滚能力，但不能自动串接在 Sol 之后。

## 6. 批改升级数据流

1. 继续执行 MiniMax 视觉 OCR、答案键优先、布局清单对齐和客观题本地保守比较。
2. Terra 对外部材料生成参考答案，并对未解决的主观题执行主批改。
3. 故障分类器只重做失败的参考答案或题目；质量分类器只提取证据充分的争议题。
4. Sol 以 `high` 重新生成参考答案或重新批改争议题，不重审已通过题目。
5. 服务层按题号合并 Sol 结果，重新执行分值汇总、置信度、答案冲突和漏题检查。
6. Sol 仍失败、漏题或低置信时保留 `provisionalScore`，最终分为空，进入教师逐题复核。
7. 教师确认前不得归档分数、错题和薄弱点，也不得向学生或家长发布。

Sol 自动升级启用后，现有风险题模型调用由 Sol 局部重做承担，不再先用 Terra 风险审查、再串行调用 Sol，避免重复审查链。

## 7. 独立兜底预算

正常 Terra 预算保持不变：

- 小测：`120000ms / 16000 tokens`；
- 普通练习：`150000ms / 16000 tokens`；
- 正式试卷和个性化练习：`240000ms / 24000 tokens`。

Sol 预算：

- 局部生成分区：每个失败分区最多 `180000ms`，token 继承该分区原上限；
- 外部参考答案或批改争议题批次：最多 `180000ms / 12000 tokens`；
- Terra 完全无可用结果时，Sol 获得一份新的完整场景预算，即小测 120 秒、普通练习 150 秒、正式试卷和个性化练习 240 秒，token 上限继承原场景；
- 每个失败单元只有一次 Sol 尝试，不因剩余时间充足而重复调用。

正常成功请求不预留或等待 Sol 预算。教师端只显示生成或批改仍在处理、已进入教师复核等产品状态，不展示模型、供应商或内部预算。

## 8. 可观测性与状态

内部 `ModelRun.metadata` 或等价流水线字段至少记录：

- `primaryModel`、`escalationModel` 和 `reasoningEffort`；
- `escalationTriggered`、`triggerClass`、`triggerCode` 和 `triggerIssues`；
- `scopeType`、分区 ID 或题号；
- Terra 与 Sol 各自延迟、token 上限、超时预算和结果状态；
- `usedModelEscalation`、`usedDynamicFallback` 和教师最终修改状态。

这些字段只供服务端、测试和内部运维使用，学生、家长、课堂平板和公共屏不得看到；教师端也不暴露密钥、base URL 或完整内部错误。

## 9. 验证与准入

### 9.1 自动测试

- 错误分类器覆盖可切换状态、不可切换状态、网络异常和空响应；
- 请求负载证明 Sol 固定发送 `model=gpt-5.6-sol` 和 `reasoning_effort=high`；
- 生成只升级失败分区，全部无结果时才整项重做；
- 批改只升级证据充分的争议题，输入证据不足不触发；
- 每个失败单元最多一次 Sol 请求，Sol 失败后不继续串行调用其他文本模型；
- 独立预算、token 继承、合并顺序、总分重算和元数据记录正确；
- Sol 成功不设置 `usedDynamicFallback`，本地动态题池才设置该标志。

### 9.2 中转和质量验证

1. 扩展 `check:gpt56`，对 Terra 和 Sol 分别使用合成输入探测能力。
2. 使用本地假服务器强制制造 `524`、超时、空响应、结构错误和低置信结果，证明不同触发路径可重复。
3. 对三科小测、正式试卷和个性化练习运行 Sol 强制升级质量样本，要求结构规则通过且不使用动态兜底。
4. 使用教师确认的批改 gold 数据比较 Terra 与 Sol 的逐题准确率、状态一致率、总分误差、不安全高置信错误率、教师修改率和延迟。
5. 在 gold 数据达到准入标准前，只能说明 Sol 升级链路可用，不能宣称批改正确率达到生产标准。

## 10. 验收标准

- Terra 正常路径的模型、档位、预算、并发和响应时间不因 Sol 配置而改变。
- 两类允许触发的问题都能按最小失败单元升级到 Sol high。
- 配置、权限、额度和证据不足问题不会误触发 Sol。
- Sol 成功结果经过完整项目校验并保留教师复核状态。
- Sol 失败后链路明确收口，不循环、不自动接入第三个文本模型。
- 模型升级不会暴露给学生、家长、课堂平板和公共屏。
- 生成质量样本、能力探测、服务层测试、API 检查和编码守卫全部通过。

## 11. 非目标

- 不把 Sol 设为日常默认模型。
- 不把 Sol 用于视觉 OCR、语音、问答、词汇、今日任务或学生档案。
- 不增加多模型投票、双模型同时生成或整卷默认二次审查。
- 不用提高 token 上限代替超时、输入证据和教师复核边界。
- 不在本轮扩大 PDF 自动排版、自动发布或自动归档能力。
