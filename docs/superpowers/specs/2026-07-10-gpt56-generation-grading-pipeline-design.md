# GPT-5.6 生成与批改内部链路设计

## 1. 目标与范围

本设计将君航 AI 助教的文本生成、参考答案、主批改和高风险裁决主链路迁移到第三方 OpenAI 兼容中转提供的 `gpt-5.6`，解决 DeepSeek V4 Pro 默认思考导致的长延迟、生成总预算挤占回退预算，以及动态兜底内容被误认为模型生成质量的问题。

目标：

- 小测、练习、试卷和教学草稿生成更快，并稳定符合项目的题型、页数、解析和教师要求。
- 图片批改优先复用项目已有答案、布局和逐题证据，提高逐题判断与总分准确率。
- 外接模型只承担内部生成、识别、判断或审查，不绕过项目服务层、教师复核和多端权限。
- 以真实样本的质量、正确率、延迟和教师修改率决定模型路由，不以模型名称代替验证。

不在本次范围内：

- 不扩大不稳定的 PDF 自动排版能力。
- 不让多模型同步审查阻塞默认草稿或默认批改返回。
- 不修改学生、家长、课堂平板和公共屏的模型可见性规则。
- 不直接使用 Codex 桌面的模型权限；项目后端只使用独立的第三方中转密钥。

## 2. 项目内容硬约束

所有模型调用必须符合君航 AI 助教现有项目内容和以下边界：

- 生成类遵守 `skills/generation/SKILLS.md`、`docs/41-prompt-context-engineering-playbook.md` 和现有 `generationContext` 契约。
- 批改类遵守 `skills/grading/SKILLS.md`、`docs/20-ocr-prestructure.md`、`docs/48-grading-workbench-redesign.md` 和逐题复核门禁。
- 小测、练习、试卷先按 `kind` 分流，继续执行语文、数学、英语各自的题型、题量、阅读、格线、图形和作答空间规则。
- 模型输出只作为草稿，进入持久化、PDF、学生端或家长端前必须经过 parse、normalize、validate、repair 和 review-state handling。
- 学生、家长、课堂平板和公共屏不得看到供应商、模型名、内部 prompt、调试字段或未复核内容。
- 低置信、漏页、题目缺失、图片质量不足、答案不可靠或模型分歧时，不给最终分、不归档、不发布。
- 教师确认前，不允许正式打印生成内容，也不允许把批改结论写入错题和学生档案。

## 3. 配置与模型角色

新增语义正确的 GPT-5.6 配置：

```dotenv
GPT56_API_KEY=
GPT56_BASE_URL=
GPT56_MODEL=gpt-5.6
GPT56_GENERATION_TIMEOUT_MS=90000
GPT56_GRADING_TIMEOUT_MS=90000
GPT56_REVIEW_TIMEOUT_MS=60000
```

迁移期间运行时可以读取旧 `GPT55_*` 作为兼容别名，但 `.env.example`、本地 `.env`、运行快照、文档和新增代码统一使用 `GPT56_*`。兼容层验证稳定后再移除旧名称。密钥不得写入 Git。

模型角色：

| 任务 | 首选 | 推理档位 | 说明 |
| --- | --- | --- | --- |
| 问答、词汇、短任务、档案草稿 | `gpt-5.6` | `none` 或 `low` | 延迟优先，仍经过项目可见性过滤 |
| 小测、普通练习、常规试卷分区 | `gpt-5.6` | `low` | 由服务层蓝图约束，不让模型自由规划整卷 |
| 偏难试卷、个性化练习、外部卷参考答案 | `gpt-5.6` | `medium` | 质量优先，但有明确超时 |
| 主观题、过程题、作文主批改 | `gpt-5.6` | `medium` | 输入必须包含题目、作答、答案和评分点 |
| 高风险争议题复判 | `gpt-5.6` | `high` | 只处理异常题，不重审整份卷 |
| 视觉 OCR、语音 | 现有 MiniMax | 现有配置 | 在 GPT-5.6 中转图片能力通过实测前保留 |
| 紧急回滚 | DeepSeek V4 Flash 非思考模式 | 关闭 thinking | 退出默认路由，只供故障回滚 |

第三方中转目前只确认支持 `gpt-5.6` 模型名，因此首期继续使用 OpenAI 兼容 Chat Completions 请求形态。是否启用 Responses API、`reasoning.effort`、JSON Schema 和图片输入，必须由能力探测确认，不能因模型名相同而假设支持。

## 4. GPT-5.6 中转能力探测

启动检查和独立脚本应验证：

1. 模型名可调用且响应中的模型标识合理。
2. 普通文本和 `json_object` 请求可用。
3. `reasoning.effort` 是否被接受、透传或忽略。
4. `json_schema` 严格结构化输出是否可用。
5. 图片输入、多个图片、`detail=high/original` 是否可用。
6. 最大输入、最大输出、单次超时、并发和限流行为。
7. 错误响应是否能区分超时、限流、参数不支持、上游不可用和内容拒绝。

能力探测不得发送真实学生数据。运行时只启用已通过探测的能力；不支持的参数由适配层关闭，服务层校验和修复继续兜底。

## 5. 生成类目标链路

### 5.1 数据流

1. 服务层组装 `generationContext`，只放入当前任务需要的教材摘要、知识点、教师重点和学生信号。
2. 服务层根据 `subject + kind + grade` 生成确定性蓝图：分区、题型、目标题量、总分、阅读长度、图形元数据和作答空间。
3. 小测和练习按 2 至 3 个分区生成；正式试卷按 3 至 5 个分区生成。独立分区使用最多 2 路有限并发。
4. GPT-5.6 只生成分区题目，不重新决定整卷结构。每个分区返回严格结构化数据。
5. 服务层合并后执行去重、结构标准化、答案与解析完整性、难度、题量、总分、图形和项目题型规则校验。
6. 只重新生成失败分区或失败题目；最多一次模型修复，之后进入明确标记的动态兜底草稿。
7. 本地审查通过后立即返回教师草稿。深度模型审查只在正式试卷、发生回退、规则检查异常或教师显式要求时异步执行。
8. 教师打开草稿 PDF 并确认后，才能导出正式学生卷与解析卷。

### 5.2 预算与回退

- 小测目标 P95 不超过 60 秒，练习不超过 75 秒，正式试卷不超过 120 秒。
- 主模型不得消耗全部总预算。首次尝试最多使用总预算的 65% 至 70%。
- 局部修复保留约 20% 预算；中转故障和回退至少保留约 15% 预算。
- 超时、限流或上游不可用才触发提供商回退；结构问题优先局部修复，不重跑整卷。
- 动态兜底必须保留 `usedDynamicFallback=true`，不能进入真实模型质量样本，也不能被描述成完整模型生成。

## 6. 批改类目标链路

### 6.1 共用前处理

1. 上传后立即入队并返回，不同步等待模型。
2. 本地 Python/OpenCV 继续负责旋转、裁边、清晰度、亮度、对比度、漏页和页序检查。
3. 多页视觉识别采用最多 2 路有限并发，输出 `printedPrompt`、`studentAnswer`、`observedWork`、`bbox`、页码和置信度。
4. 任何识别阶段都必须区分印刷题干、学生作答、示例答案和教师批改痕迹。

### 6.2 本系统生成卷

1. 按 `assignmentId` 读取 `answerKey`、`assignmentItems` 和 `questionLayoutManifest`。
2. 使用真实布局区域裁切或定位学生作答，只识别作答区，不重新猜整页题目。
3. 选择、判断、明确填空、数值和单位可标准化的题目优先使用确定性比较。
4. 解答题、过程题、阅读简答、英语表达和作文交给 GPT-5.6 逐题评分。
5. 模型输入只包含当前题的题干、学生作答、标准答案、解析、评分点、分值和必要图片证据。

这是项目最高准确率路径，不调用模型重新生成参考答案。现有 `prepareSubmissionReferenceAnswers` 的答案键优先行为必须保留。

### 6.3 外部材料

1. 视觉模型提取题干、材料、学生作答和区域。
2. GPT-5.6 使用 `medium` 生成逐题参考答案、解析和评分点，并标记每题置信度。
3. 参考答案低置信的题直接进入教师复核，不作为自动评分依据。
4. 客观题走确定性比较；主观题由 GPT-5.6 按题评分。
5. 只对低置信、答案冲突、异常得分、图形证据不足和总分不一致的题调用高风险复判。

### 6.4 归档门禁

- 每题保存状态、得分、满分、学生答案、正确答案、错误步骤、解释、知识点、置信度和图片坐标。
- 总分由服务层根据逐题得分计算，模型不能直接覆盖总分。
- 任一题 `uncertain`、低置信、漏页或证据不足时，只保留 `provisionalScore`。
- 高风险复判失败或中转不可用时进入教师复核，不继续串行调用多个模型。
- 所有题目仍须教师逐题确认，之后才允许归档分数、错题和薄弱点。

## 7. 提示词与结构化输出

- 把重复的项目规则留在服务层蓝图和 JSON Schema 中，模型提示只包含当前任务必要约束。
- 保留模型角色、任务类型、教学约束、审核边界和多端可见性，但删除在 system 和 user 消息中重复出现的内容。
- 中转支持 JSON Schema 时使用严格 Structured Outputs；否则使用 `json_object`，继续执行现有 parse、normalize、validate 和 repair。
- 生成和批改使用不同 schema；小测、练习、试卷使用不同蓝图；客观题和主观题使用不同批改策略。
- 不要求模型输出无用的长篇解释。解析字段按项目实际打印和教师复核需要生成。

## 8. 可观测性与回滚

`ModelRun.metadata` 和生成/批改流水线记录：

- 逻辑角色、实际提供商、模型、接口形态和能力探测版本。
- 推理档位、输入/输出 token、首 token 时间、总延迟和超时预算。
- 分区或题号、尝试次数、错误分类、局部修复和回退原因。
- 是否使用动态兜底、是否进入风险复判、教师最终修改情况。

学生和家长端过滤这些内部字段。运行时保留受控回滚开关，使 GPT-5.6 中转整体故障时可以切到 DeepSeek V4 Flash 非思考模式；不使用 DeepSeek V4 Pro 作为默认同步回退。

## 9. 验收与评测

### 9.1 生成评测集

固定覆盖三科、小测/练习/试卷、三至六年级、基础/综合/偏难、教材上下文和个性化薄弱点。每份由教师按以下指标评分：

- 教师要求贴合度。
- 答案正确率和解析正确率。
- 年级、难度和知识点匹配度。
- 题型与项目规则合规率。
- 重复题、同质题和模板化比例。
- 结构修复率、动态兜底率和教师修改率。
- P50、P95 延迟和单份成本。

准入要求：结构规则 100% 通过；答案和解析抽检达到教师确认的上线标准；动态兜底不计入模型质量通过；速度达到第 5.2 节目标或明确说明差距。

### 9.2 批改金标准集

由教师确认真实题目、学生作答、逐题状态、逐题得分、总分和错误步骤，分别覆盖本系统生成卷与外部材料。指标：

- 客观题逐题准确率。
- 主观题状态一致率与得分误差。
- 总分绝对误差。
- 错误步骤和知识点归因准确率。
- 低置信召回率，以及把错误结果错误放行为高置信的比例。
- OCR 题号/作答对齐率、教师逐题修改率和整份处理时延。

没有金标准评测结果前，只能说明链路可用或速度改善，不能宣称批改正确率已经达到生产标准。

## 10. 实施顺序

1. 新增 GPT-5.6 配置、兼容适配层和无学生数据的能力探测。
2. 建立生成 A/B 样本，迁移问答、任务和生成主路由。
3. 将整卷单请求改为服务层蓝图加分区有限并发，并重做预算分配。
4. 建立批改金标准集，保留答案键优先并加入客观题确定性比较。
5. 迁移参考答案和主观题主批改，加入按风险逐题复判。
6. 更新运行手册、状态快照、项目 Skills、API 契约和分层验证脚本。
7. 通过真实质量与延迟门禁后，退出 DeepSeek 默认路由，仅保留短期回滚。

按改动范围运行：

```powershell
cmd /c npm.cmd run check:generation:blueprint
cmd /c npm.cmd run check:generation:quality:quiz
cmd /c npm.cmd run check:generation:quality:formal
cmd /c npm.cmd run check --workspace apps/api
cmd /c npm.cmd run check:content-context
cmd /c npm.cmd run check:encoding
```

新增能力探测、生成 A/B 和批改金标准评测必须独立输出机器可读结果，不能让真实中转测试变成普通单元测试的强依赖。
