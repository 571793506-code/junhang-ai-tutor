# 学生端个人词汇本设计（已废弃）

## 状态与范围

本设计已于 2026-07-16 被 `2026-07-16-student-english-dictionary-design.md` 替代。学生端不再建设个人词汇本，改为不关联学生个人数据的共享英语词典查询。

以下内容仅保留为历史设计记录，不再作为实现依据。

本期包含：

- 学生输入一个或多个英文单词，由服务端生成完整词卡。
- 学生读取自己的词汇本列表。
- 再次添加同一单词时更新已有词卡，不创建重复项。
- 学生删除自己的单条词卡。

本期不包含：

- 学生手写释义、例句、笔记或编辑 AI 生成内容。
- 词汇发音、听写、测验、教师词库管理或学生间共享。
- 在小程序端拼接 prompt、模拟词卡或保留本地静态词典。

## 现状与问题

当前小程序页面只在 `dictionary` 中匹配 `carry`、`bright`、`go`，并把查询结果覆盖为单个 `result`。它没有调用 API、没有词卡列表，也没有删除操作。

当前服务端 `POST /api/ai/vocabulary` 会生成一张词卡，并在有学生 ID 时追加 `VocabularyRecord`。该记录被教师审计接口读取，不具备按学生读取词汇本、按词去重更新或学生删除的语义。

因此，个人词汇本不能复用 `VocabularyRecord` 作为唯一的数据实体。否则，学生删除学习卡会混淆或删除既有审计记录，重复查询也会持续追加记录。

## 方案选择

采用独立的 `VocabularyEntry` 实体作为个人词汇本，保留现有 `VocabularyRecord` 的既有用途。

未采用的方案：

- 直接删除或改造 `VocabularyRecord`：实现较短，但把可删除的学生内容与查询审计混在一起。
- 在小程序本地缓存词卡：不能跨设备同步，不满足本期必须走数据链路的要求。

## 数据模型

新增 `VocabularyEntry`：

- `id`：词卡 ID。
- `studentId`：所属学生。
- `word`：规范化后的英文单词。
- `card`：完整、已规范化的词卡 JSON，包含单词、音标、词性及中文说明、释义、相关词、例句和易错点。
- `createdAt`、`updatedAt`：用于列表排序和更新判断。

数据库为 `(studentId, word)` 建立唯一约束。服务端将输入去除首尾空白并转为小写后再写入；同一学生再次添加同一单词时使用 upsert 更新 `card` 和 `updatedAt`。

现有 `VocabularyRecord`、种子数据和教师审计映射不迁移、不删除，也不作为学生词汇本的读取来源。

## 服务端契约

新增学生会话专用接口，避免客户端传递可伪造的 `studentId`：

| 方法 | 路径 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| `POST` | `/api/student/vocabulary` | `{ words: string[] }` | 词卡新增或更新结果，以及逐词失败摘要 |
| `GET` | `/api/student/vocabulary` | 无 | 当前登录学生的词卡列表，按 `updatedAt desc` 排序 |
| `DELETE` | `/api/student/vocabulary/:entryId` | 无 | 已删除词卡的 ID |

`POST` 只接受非空英文单词；单次最多处理有限数量，服务端会去重。输入格式解析由小程序负责：每行一个单词，或以英文/中文逗号分隔。服务端仍必须重新校验，不能相信客户端解析结果。

批量生成允许部分失败：成功单词立刻写入词汇本；失败单词只返回学生可理解的提示，不创建空卡或伪造静态卡。响应不得包含模型名、供应商、prompt、原始模型输出、审计 ID 或数据库细节。

`GET` 和 `DELETE` 都从已认证的学生会话确定归属。尝试删除不属于当前学生的词卡时，返回通用的无权限或不存在结果，不能泄露其他学生的词卡信息。

既有 `POST /api/ai/vocabulary` 保持兼容，供已存在的 Web 词卡生成入口使用；个人词汇本 API 使用共享服务层的词卡生成和规范化逻辑，不在路由或小程序中复制生成逻辑。

## 服务层

新增词汇本服务层，职责为：

1. 规范化和去重输入单词。
2. 调用现有词卡生成能力，取得已规范化的完整词卡。
3. 在生成成功后对 `VocabularyEntry` 执行 upsert。
4. 以角色安全的 DTO 返回词卡列表、批量结果和删除结果。

批量任务按受控顺序处理，避免一次输入导致无界并发调用。任何单词生成失败不会阻断其余单词；服务层汇总每个单词的成功或失败状态。

## 小程序交互

词汇页在 `onShow` 完成学生身份检查后读取词汇本。页面状态包含：加载中、空词汇本、提交中、批量部分失败、删除中和通用可读错误。

学生在文本框中输入单词并点击“生成词卡”。成功后清空输入并从服务端刷新完整列表。页面只渲染接口返回的词卡；移除当前的 `dictionary`、`fallback` 和默认静态 `result`。

每张词卡展示单词、词性和中文说明、释义、易错变化或提示；删除操作要求确认，并在成功后从服务端刷新列表。页面不展示模型、供应商、内部 ID、持久化状态或失败技术细节。

## 测试与验证

先写并观察失败的测试，再实现：

1. 服务层：输入规范化、批量去重、同词 upsert、部分生成失败不写空卡。
2. API：学生只读取自己的词卡、学生不能删除他人词卡、批量新增返回学生可见字段。
3. 小程序：使用新增 API wrapper，页面不再引用 `dictionary` 或 `fallback`，并具备新增、读取、删除事件。
