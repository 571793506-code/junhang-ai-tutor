# 页面结构草案

先做 Web 模拟端，用来确定小程序页面、数据流和老师后台逻辑。

## 2026-11-10 教师端日常使用调整

- 首页突出日常入口与最近登记材料，原型展示说明默认收起；历史批改不因首页统计触发重新评分或归档。
- 生成页区分“新建内容”和“已有成果 / 继续修改”。打开成果后收起任务列表，题干直接阅读，完整生成要求、答案解析、评分细则分别展开；切换区域保留未提交输入，版本冲突仍保留本地编辑。
- 教材资料默认进入教材检索；资料来源检索与复核、资料导入与索引管理分区。分区切换保留所选文件和登记输入，受保护教材及教师审批门禁保持原规则。
- 学生档案先显示当前学生概览、档案周期和已加载来源，再编辑周/月档案与阶段报告。发布提示依据当前保存快照的 `draftStatus`，不把有草稿当作学生端可见。未明确绑定学生的通用日志不显示为该生证据。
- 今日任务默认跟随上方选择的学生，可改看全部学生，并按日期、完成状态筛选及分页。日期使用 API 的 `dueAt`，缺少时使用 `createdAt`；两者均缺失时显示“日期未记录”，不从“今日”等旧标签猜日期。任务正文和完成照片上传按需展开。
- 这些入口继续复用共享 API、版本、教师确认与导出契约；其他端后续可沿用同一数据结构。当前不修改整体配色，不增加同卷多人自动分组批改。
- 本轮布局以电脑 Web 和 iPad 横屏、竖屏为验收目标，暂不推进手机端适配。iPad 使用紧凑横向导航，生成工作区切换阅读、修改和要求，触控控件保留至少 44px 高度。

验证入口：`check:web:teaching-generation`（含任务筛选、资料切区保留、档案状态、电脑与 iPad 视口）、`check:web:teaching-grading`、Web typecheck、`check:content-upload-ui`、`check:encoding`。浏览器合成数据回归不替代真实教学内容验收。

## 2026-11-10 教师端 B＋C 融合视觉

- 采用已确认的深浅分区模板：午夜深色导航、顶部及生成/批改操作区，白色题目、原卷与解析阅读区；紫色用于内容选择与主要入口，青色用于深色区域的当前导航与确认操作。
- 教师视觉变量集中在 `apps/web/src/teacher-theme.css`，不改学生与课堂端主题。各模块使用有区分的导航图标，电脑与 iPad 沿用现有导航和工作区切换；iPad 控件保留 44px 触控高度。
- 正确、错误与待核对保留各自状态文字和语义色；选中颜色不改变评分状态。教师最终评分、逐题确认、独立归档及所有 API 契约沿用原流程。
- 验证：Web typecheck、源码编码检查及 diff 检查通过；真实教师端检查覆盖工作台、生成、批改、资料和档案，电脑 1600/1280px 与 iPad 1024×768、768×1024 阅读区未见横向溢出。生成工作台、旧批改归档就绪状态、归档历史三项浏览器用例并行运行超时后，串行重跑均通过。实际页面截图保存在 `tmp/quality/teacher-bc-theme-20261110/`。历史验收卷仍有指向旧局域网地址的原图无法加载，本次只记录该问题，不改历史证据。
