# 第一版功能清单与范围确认

## 1. 范围原则

第一版目标不是一次性完成全部想法，而是形成一个可展示、可使用、可继续扩展的闭环。

优先级判断：

1. 已经在 Web 端或小程序中存在基础能力的功能优先。
2. 能直接支撑家长信任、学生参与、老师可控的功能优先。
3. 只停留在概念层的新互动玩法，第一版先做入口或视觉原型。
4. 需要大量实时同步、复杂数据统计或新业务表的功能先暂缓。

## 2. 第一版总体目标

第一版建议形成四个核心闭环：

1. 老师发布任务，学生查看并完成。
2. 学生或老师上传作业图片，AI 初步识别和批改，老师复核。
3. 学习记录沉淀到学生档案，老师确认后发布反馈。
4. 平板端和电视端展示整体学习过程，增强现场科技感和家长信任感。

## 6. 电视动态屏 V1

### 6.1 V1 定位

电视动态屏第一版建议先做“展示型大屏”，不做复杂实时投屏协议。

可通过浏览器大屏或本地 Web 页面展示。

### 6.2 V1 必须做

| 模块 | 数据来源 |
| --- | --- |
| 今日学习运行概览 | tasks、submissions、grading、review 统计 |
| AI 学习中枢 | 根据任务、提交、识别、复核、归档计数展示 |
| AI 处理队列 | submission/review 状态统计 |
| 多年级任务分布 | students、tasks 按年级聚合 |
| 实时学习动态 | behaviorEvents/audit events 匿名展示 |
| 学科知识互动热力 | tasks、mistakes、qa、submissions 按学科和知识点聚合 |

### 6.3 V1 展示原则

- 不显示学生头像墙。
- 不显示个人姓名。
- 不显示个人分数。
- 不显示排名。
- 只展示整体、匿名、过程数据。

### 6.4 V1 实现方式

第一版可以先使用：

- Web 端独立大屏路由或静态页面
- 模拟数据 + 已有 bootstrap 数据
- 后续再接真实聚合 API

## 7. Web 端 V1 角色

当前 Web 端不只是临时页面，可以作为第一版设计和数据闭环验证工具。

V1 Web 端建议承担：

1. 教师端后台模拟与实际操作。
2. 学生端页面预览。
3. 平板端交互原型。
4. 电视动态屏展示原型。
5. API 和数据闭环验证。

## 8. 第一版不做清单

为了控制范围，以下内容建议暂缓：

- 完整学习小队挑战系统
- 长期小队排行
- 课堂投票完整闭环
- 电视端复杂实时同步协议
- 家长独立端
- 全量教材知识图谱
- 完整语音识别与语音评分
- 虚拟人物讲解
- 3D 教学实验室
- AI 自动发布未复核报告

## 9. 第一版推荐开发顺序

### Step 1：主题 UI 落地

- 把现有学生端、教师端、平板端换成统一主题。
- 保留已有功能结构，不大改数据流。

### Step 2：电视动态屏原型

- 建立独立展示页面。
- 使用现有 bootstrap/audit 数据做聚合展示。
- 先保证大屏视觉和匿名原则。

### Step 3：平板拖拽交互原型

- 做四周头像轨道。
- 做学习光环拖拽吸附。
- 做身份确认和插件选择。

### Step 4：教师端展示控制入口

- 增加“打开电视动态屏”。
- 增加“平板展示模式”简单开关。
- 第一版不做复杂配置。

### Step 5：接入真实统计

- 从 API 聚合今日任务、提交、复核、学科互动等数据。
- 替换电视动态屏模拟数据。

## 10. 第一版验收标准

V1 完成后应能演示：

1. 老师登录后能管理学生、发布任务、生成练习和批改。
2. 学生登录后能查看任务、问答、词汇、档案和拍照提交。
3. 作业提交后能进入批改复核队列。
4. 老师复核后能写入学生档案。
5. 平板端能展示公共主页和头像确认交互。
6. 电视端能展示多年级匿名动态数据。
7. 整体视觉统一，有温和科技感。
8. 公共屏不出现排名、个人分数和隐私信息。
