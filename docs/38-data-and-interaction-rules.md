# 数据展示与互动规则设计

## 1. 设计目标

这份文档用于补充 Web 原型背后的规则，避免后续只迁移界面而丢失产品逻辑。

覆盖范围：

- 电视动态屏数据展示规则。
- 学科知识互动热力含义。
- 平板公共端拖拽解锁规则。
- 平板互动插件启用规则。
- 学生端模块状态规则。
- 公共屏隐私边界。

## 2. 电视动态屏数据规则

### 2.1 今日学习运行概览

展示字段：

| 字段 | 含义 | 可用来源 |
| --- | --- | --- |
| 学习任务 | 今日任务 + 练习/小测/试卷数量 | `tasks`、`assignments` |
| 已完成 | 状态为已完成的任务数量 | `tasks.status` |
| AI 处理 | 生成、识别、批改、问答等 AI 处理记录数量 | `assignments`、`reviewSubmissions`、后续 `modelRuns` |
| 老师复核 | 待复核或已复核数量 | `reviewSubmissions` |

展示原则：

- 可以显示数量。
- 不显示学生姓名。
- 不显示个人完成率。
- 不显示排名。
- 数据不足时使用“今日记录正在生成”的占位，不显示空白。

顶部信任链建议显示：

- 过程可追踪。
- AI 先分析。
- 老师再复核。
- 阶段可归档。

### 2.2 AI 学习中枢

固定流程：

1. 教师发布。
2. 学生学习/提交。
3. AI 识别分析。
4. 老师复核。
5. 学生端反馈。
6. 阶段归档。

当前节点高亮规则：

| 数据状态 | 高亮节点 |
| --- | --- |
| 有今日任务 | 教师发布 |
| 有提交/上传 | 学生学习/提交 |
| 有待识别/待批改 | AI 识别分析 |
| 有待复核 | 老师复核 |
| 有已发布报告 | 学生端反馈 |
| 有档案发布 | 阶段归档 |

第一版可以先固定高亮“AI 识别分析”，后续再按数据状态动态切换。

推荐在中枢下方保留一句家长可读说明：

> AI 先分析，老师再复核。任务、提交、识别、反馈和档案形成一条可追踪的学习链路。

### 2.3 AI 处理队列

队列项建议：

| 队列项 | 含义 |
| --- | --- |
| 图片识别 | 拍照提交后等待 OCR 或已进入 OCR |
| 老师复核 | AI 初稿等待老师确认 |
| 反馈归档 | 老师确认后写入学生端和档案 |
| 任务同步 | 教师发布任务同步到学生端 |

展示规则：

- 使用匿名状态。
- 不展示具体学生。
- 不展示原始作业图片。
- 可展示数量和状态流动。

### 2.4 多年级任务分布

展示内容：

- 三年级。
- 四年级。
- 五年级。
- 六年级。

计算规则：

```text
年级任务量 = 该年级学生相关 tasks + 该年级 assignments
```

注意：

- 显示整体分布，不显示具体班级排名。
- 不要使用“领先、落后、最高、最低”等比较性词语。
- 条形图只代表任务/记录数量，不代表学习好坏。

### 2.5 实时学习动态

匿名事件格式：

```text
学科/流程标签 + 事件描述 + 状态说明
```

示例：

- 英语：词汇订正已进入老师复核。
- 数学：应用题练习已完成 AI 初筛。
- 语文：阅读概括任务已同步学生端。

事件密度：

- 电视端建议同时保留 4 到 6 条可读事件。
- 真实日志不足时，可从任务同步、错题观察、反馈归档中生成匿名状态事件。
- 展示事件必须能解释学习过程，不使用纯装饰性随机文案。

禁用内容：

- 学生姓名。
- 家长姓名。
- 手机号。
- 单个学生错题全文。
- 单个学生问答全文。
- 个人得分。

## 3. 学科知识互动热力规则

### 3.1 热力含义

学科知识互动热力不是成绩，也不是完成度。

它表示：

> 某个学科或知识点在任务、问答、批改、错题订正中的互动频次。

颜色含义：

| 颜色 | 含义 |
| --- | --- |
| 浅色 | 互动较少 |
| 中色 | 有一定互动 |
| 深色 | 互动频繁 |

第一版热力带建议每个学科展示 24 个色块，充分利用电视横向空间。

### 3.2 互动来源

可计入热力的数据：

| 来源 | 示例 |
| --- | --- |
| 今日任务 | 老师发布的数学应用题任务 |
| AI 问答 | 学生询问某个知识点 |
| 拍照提交 | 作业或小测提交 |
| 批改复核 | AI 批改、老师复核 |
| 错题订正 | 错因、知识点、订正状态 |
| 课文跟读/听写 | 英语词汇、语文课文 |

### 3.3 不可表达成

热力图不能表达为：

- 哪个学生更好。
- 哪个学生更差。
- 哪个年级最差。
- 某个学生错题最多。
- 某个学生任务没完成。

推荐说明文案：

> 颜色越深，代表该学科知识点在任务、批改、问答和订正中的互动次数越高。这里只展示整体趋势，不展示学生个人表现。

## 4. 平板公共端拖拽解锁规则

### 4.1 状态机

| 状态 | 说明 |
| --- | --- |
| idle | 公共待机展示 |
| dragging | 学生拖拽头像中 |
| confirmed | 头像进入学习光环，确认本次互动身份 |
| plugin | 显示可用插件 |
| timeout | 超时回到待机 |

### 4.2 拖拽规则

Web 原型：

- 使用 `draggable`。
- 拖入中心区域后 `drop`。
- 成功后设置 `activeStudentId`。
- 拖拽开始后，当前头像放大，其余头像降低亮度。
- 中心学习光环放大并显示“中心吸附区”。
- 进入中心后提示“松手即可吸附确认”。

小程序迁移建议：

- 第一轮可先点击头像确认。
- 第二轮使用 `touchstart / touchmove / touchend` 实现拖拽。
- 根据头像中心点是否进入光环区域判断是否吸附。

### 4.3 头像显示规则

允许显示：

- 卡通头像。
- 学生昵称或姓名。
- 上、下、左、右头像轨道标签。

不允许显示：

- 成绩。
- 排名。
- 完成度。
- 风险标签。
- 家长联系方式。
- 个人档案摘要。

### 4.4 解锁后显示

显示：

- 当前学生头像。
- 当前学生名字。
- “已进入本次互动”。
- “本次记录将同步到学习档案”。
- 插件选择。

不显示：

- 个人主页。
- 完整学生档案。
- 错题详情。
- 个人分数。

## 5. 平板互动插件规则

### 5.1 第一版插件状态

| 插件 | 状态 | 说明 |
| --- | --- | --- |
| AI 问答 | 可用 | 进入课堂问答 |
| 听写播报 | 可用 | 老师开启后播报 |
| 课文跟读 | 可用 | 进入跟读任务 |
| 课堂投票 | 入口 | 后续扩展 |
| 今日鼓励 | 入口 | 后续扩展 |
| 小组协作 | 入口 | 后续扩展 |

### 5.2 插件启用规则

未确认学生前：

- 插件低亮。
- 不进入插件主流程。
- 文案：拖拽头像后开启。

确认学生后：

- AI 问答、听写播报、课文跟读可进入。
- 入口型插件只展示“老师开启后可用”。

插件视觉状态：

| 状态 | 展示方式 |
| --- | --- |
| 未解锁 | 低亮，提示拖拽头像后开启 |
| 已解锁可用 | 高亮，表示可以进入已有能力 |
| 老师开启后 | 虚线或低强调色，表示后续入口 |

### 5.3 自动回到待机

建议规则：

- 互动结束后自动回到公共待机。
- 身份确认后长时间无操作，自动回到公共待机。
- 第一版建议超时为 60 到 90 秒。
- 超时只清除本次互动身份，不影响学生档案记录。

### 5.4 插件使用记录

后续如果记录互动事件，建议字段：

| 字段 | 含义 |
| --- | --- |
| `studentId` | 当前确认学生 |
| `deviceId` | 当前平板 |
| `pluginType` | 插件类型 |
| `startedAt` | 开始时间 |
| `endedAt` | 结束时间 |
| `result` | 简短结果 |
| `reviewRequired` | 是否需要老师复核 |

## 6. 学生端模块状态规则

### 6.1 首页模块

| 模块 | 状态摘要 |
| --- | --- |
| 今日任务 | 今日任务数量 |
| AI 问答 | 可用 / 暂不可用 |
| 英语词汇 | 词汇助手 / 单词查询 / 易错变化 |
| 拍照提交 | 已提交数量 / 等待提交 / 提交后等待老师查看 |
| 学生档案 | 已发布反馈 / 待巩固数量 / 老师复核后同步 |
| 互动扩展 | 老师开启后可用 / 不做公开排名 |

首页建议增加两个温和摘要：

| 摘要 | 内容 |
| --- | --- |
| 今天先做什么 | 优先展示最近一项老师发布的任务 |
| 温和反馈 | 展示最近学习动态或“提交后等待老师查看” |

### 6.2 模块排序

推荐顺序：

1. 今日任务。
2. AI 问答。
3. 英语词汇。
4. 拍照提交。
5. 学生档案。
6. 互动扩展。

理由：

- 前四个是学生日常使用高频模块。
- 学生档案偏家长查看和阶段反馈。
- 互动扩展目前不是第一版主流程。

视觉层级：

- 今日任务可以作为主入口，占更大空间。
- AI 问答、英语词汇、拍照提交、学生档案为常规入口。
- 互动扩展使用低强调或虚线样式，避免被误认为第一版核心功能。

### 6.3 文案原则

推荐：

- “先完成老师发布的任务。”
- “遇到不会的题，可以先看思路。”
- “提交后等待老师查看。”
- “老师复核后会同步到学习档案。”

避免：

- “你落后了。”
- “你的完成度最低。”
- “赶快超过其他同学。”
- “错题太多。”

## 7. 教师端控制规则

### 7.1 电视动态屏入口

建议教师端显示：

- 打开电视动态屏。
- 复制大屏地址。
- 查看大屏数据状态。
- 当前是否匿名展示。
- 当前是否适合家长参观。

第一版不需要复杂配置。

### 7.2 平板展示模式

建议模式：

| 模式 | 用途 |
| --- | --- |
| 常规待机 | 日常课堂间隙 |
| 家长参观 | 数据更丰富，强调整体过程 |
| 课堂互动 | 强调插件和当前任务 |
| 听写锁屏 | 听写期间不显示答案 |

### 7.3 插件开关

第一版只需要：

- 可用。
- 暂停。
- 老师开启后可用。

不做复杂规则。

### 7.4 展示与互动控制台边界

教师端控制台第一版承担三个作用：

- 说明谁控制公共展示。
- 说明哪些能力已可用，哪些只是入口。
- 作为后续小程序迁移前的配置草稿。

第一版不承担：

- 真实远程开关。
- 小程序页面迁移。
- 插件行为闭环。
- 家长端可见配置页。

教师端可以显示：

| 区域 | 教师端显示 | 学生/家长端显示 |
| --- | --- | --- |
| 电视动态屏 | 预览、地址、匿名状态 | 整体趋势和复核链路 |
| 平板展示模式 | 常规待机、家长参观、课堂互动、听写锁屏 | 当前公共屏状态 |
| 插件开关 | 可用、老师开启后、暂停 | 可用或暂不可用 |
| 迁移配置 | 迁移顺序和注意事项 | 不显示 |

## 8. 统一禁用清单

公共展示中禁用：

- 学生公开排名。
- 课堂实时榜。
- 单个学生完成度能量条。
- 个人分数。
- 个人错题详情。
- 家长手机号。
- 家长姓名。
- 学生隐私档案。
- “领先/落后/超过”等强比较文案。
