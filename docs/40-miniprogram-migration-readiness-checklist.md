# 小程序迁移前最终核对表

## 1. 当前结论

当前阶段已经进入迁移准备和第一轮页面落位。

迁移前的产品结论：

- 小程序启动页必须先做统一身份选择和登录门禁。
- 学生端优先迁移模块化首页。
- 平板端优先迁移公共待机和头像确认结构。
- 教师端只补展示控制入口，不做复杂配置。
- 电视动态屏第一版继续保留 Web 大屏。
- 互动扩展只做入口，不做完整 PK、投票、鼓励或协作闭环。

当前执行线：

> 可以修改 `apps/miniprogram/pages/*` 进行第一轮小程序导入准备；复杂拖拽、完整互动闭环和电视动态屏小程序页暂缓。

## 4. 交互边界

### 4.1 学生端

必须保留：

- 模块选择 -> 进入模块 -> 执行操作。
- 今日任务作为主入口。
- AI 问答只强调思路引导。
- 学生档案只展示老师复核并发布后的内容。

禁止出现：

- 公开排名。
- 超越同学。
- 个人完成度能量条。
- 课堂实时榜。
- 未发布的档案草稿。

### 4.2 平板端

必须保留：

- 平板是公共设备。
- 只确认本次互动身份。
- 未确认身份时插件低亮。
- 确认身份后才进入插件。
- 互动结束或超时回到公共待机。

第一轮可降级：

- 拖拽吸附可先用点击头像确认替代。
- 插件开关可先做展示状态。
- 互动事件可先不入库。

禁止出现：

- 完整学生个人主页。
- 个人成绩和排名。
- 个人任务完成度条。
- 家长手机号和隐私档案。

### 4.3 电视动态屏

必须保留：

- 多年级匿名展示。
- 动态数据化。
- AI 先分析、老师再复核。
- 学科知识互动热力解释。
- 数据不足时不空屏。

禁止出现：

- 学生头像墙。
- 学生姓名。
- 课堂实时榜。
- 个人分数。
- 个人完成度。

### 4.4 教师端

必须保留：

- 教师端控制学生权限、任务、生成打印、批改复核、学生档案发布、教材资料、课堂设备和系统状态。
- 教师端可以显示服务状态。
- 教师端可以看到展示控制入口。

第一轮可降级：

- 电视动态屏入口先显示地址提示，不做真正二维码。
- 平板展示模式先做视觉状态，不落库。
- 插件开关先做状态说明，不控制真实插件。

## 5. 迁移执行顺序

建议正式迁移时按下面顺序：

1. 小程序统一登录入口。
2. 学生、教师、平板三类登录页主题统一。
3. 学生端首页 UI。
4. 学生端模块入口状态。
5. 平板端公共待机 UI。
6. 平板端头像确认。
7. 平板端插件栏状态。
8. 教师端展示与互动控制入口。
9. 教师端电视大屏地址提示。
10. 回头补平板拖拽吸附。
11. 评估是否新增展示配置接口。

不建议第一轮就做：

- 完整拖拽事件入库。
- 完整课堂投票。
- 完整学习小队 PK。
- 电视动态屏小程序页面。
- 新增复杂教师配置页。
