# 君航 AI 助教第一版功能清单

## 1. 第一版定位

第一版不追求把所有互动想法一次性做完整，而是先形成一个能够展示、能够使用、能够让家长建立信任的闭环版本。

核心目标：

1. 学生端可以完成日常学习任务、AI 问答、词汇辅助、拍照提交和查看学习档案。
2. 平板端可以作为公共设备展示整体学习氛围，并通过头像拖拽完成短时互动身份确认。
3. 电视动态屏可以面向家长展示匿名化、多年级、动态化的学习过程数据。
4. 教师端可以完成发布、生成、批改、复核、归档和基础展示控制。
5. 整体视觉先统一为“温和科技感”，AI 感通过数据流、状态变化、流程可视化和交互反馈体现。

## 2. 当前项目已有基础

### 2.1 Web 端已有模块

当前 Web 端已经具备三类角色入口：

| 角色 | 当前模块 |
| --- | --- |
| 教师端 | 工作台、学生权限、今日任务、生成打印、批改复核、学生档案、教材资料、课堂设备、电视动态屏、系统状态 |
| 学生端 | 主页、今日任务、AI 问答、学生档案 |
| 课堂/平板端 | 课堂主页、语音问答、听写播报、课文跟读 |

这些模块可以作为第一版产品逻辑和视觉改造的主要基础。

### 2.2 小程序端已有页面

| 端 | 已有页面 |
| --- | --- |
| 学生端 | 登录、主页、今日任务、AI 问答、英语词汇助手、学生档案、拍照提交 |

| 平板端 | 登录、课堂 dashboard |
| 公共入口 | 角色选择 |

### 2.3 API 与数据能力基础

当前服务端已经覆盖这些能力：

- 学生、教师、平板登录。
- 基础数据 bootstrap。
- AI 问答。
- 学生注册、权限开关、专属码重置。
- 教师发布今日任务。
- 练习、小测、试卷生成和打印导出。
- 学生/教师拍照提交。
- AI 识别与批改复核。
- 学生档案聚合、草稿生成、教师发布。
- 课堂听写、课文跟读、广播、语音问答。
- 平板设备锁定、解锁、设备状态读取。
- 教材库扫描、章节维护和打开。
- 审计记录与服务状态查看。

## 3. 第一版总功能边界

### 3.1 第一版必须做

| 功能方向 | 第一版目标 |
| --- | --- |
| 主题 UI 统一 | 学生端、平板端、电视端、教师端统一为温和科技感视觉 |
| 学生学习闭环 | 任务查看、AI 问答、词汇辅助、拍照提交、档案反馈 |
| 教师工作闭环 | 学生管理、任务发布、组卷生成、批改复核、档案发布 |
| 平板公共互动 | 公共展示、头像四周分布、拖拽吸附解锁、插件选择 |
| 电视动态屏 | 匿名化动态数据展示，突出 AI 分析、老师复核、学习归档 |
| 数据安全边界 | 公共屏不展示排名、分数、个人完成度和敏感信息 |

### 3.2 第一版只做入口或原型

| 功能方向 | 第一版处理 |
| --- | --- |
| 学习小队挑战 | 学生端保留互动模块入口或概念展示，不进入主流程 |
| 课堂投票 | 平板端可作为插件入口展示，完整闭环暂缓 |
| 今日鼓励 | 平板端可作为插件入口展示，先不做复杂生成规则 |
| 小组协作 | 平板端可作为插件入口展示，第一版不做完整协作系统 |
| 电视动态数据 | 先使用已有数据聚合加少量模拟动态，后续再接完整实时统计 |

### 3.3 第一版暂不做

- 学生长期公开排名。
- 课堂实时榜。
- 单个学生在公共屏上的任务完成度能量条。
- 电视端学生头像墙。
- 家长独立端。
- 完整学习小队 PK 系统。
- 完整课堂投票闭环。
- 复杂实时投屏协议。
- 虚拟人讲解。
- 3D 教学实验室。
- 未经老师复核的 AI 自动发布报告。

## 4. 学生端 V1 功能清单

学生端是第一版重点之一，必须贴合现在小程序已有模块，避免新增过多不稳定入口。

### 4.1 必做模块

| 模块 | 功能内容 | V1 处理 |
| --- | --- | --- |
| 登录 | 姓名、家长电话、学生专属码登录 | 保留并优化视觉 |
| 首页 | 今日任务概览、待完成练习、掌握情况、功能模块入口 | 重做主题 UI |
| 今日任务 | 查看老师发布任务、任务状态、预计用时、提交入口 | 保留主流程 |
| AI 问答 | 文本提问、AI 引导回答、问答结果展示 | 保留并强化 AI 反馈样式 |
| 英语词汇助手 | 单词解释、词性、变化、易错点 | 保留为独立模块 |
| 学生档案 | 掌握情况、错题记录、阶段反馈 | 强调“老师复核后发布” |
| 拍照提交 | 上传作业、练习、小测、试卷、听写 | 保留并统一状态 |

### 4.2 首页模块展示建议

学生端首页不建议做成长篇信息流，建议采用几大模块入口：

1. 今日任务。
2. AI 问答。
3. 英语词汇。
4. 拍照提交。
5. 学生档案。
6. 互动扩展。

点击某个模块后，再进入模块内部操作。

### 4.3 互动扩展处理

“本周学习小队挑战”可以保留为后续扩展方向，但第一版不作为主流程。

建议第一版只展示：

- 互动扩展入口。
- 老师开启后才显示具体活动。
- 文案偏向共同完成、共同点亮，不做公开 PK 排名。

## 5. 平板公共端 V1 功能清单

平板端是第一版重点之一，但它是一个年级或班级共享设备，不是每个学生个人设备。

### 5.1 必做模块

| 模块 | 功能内容 | V1 处理 |
| --- | --- | --- |
| 设备登录/绑定 | 通过绑定码进入平板端 | 保留 |
| 公共待机页 | 今日学习概览、AI 工作流、课堂任务状态 | 新增视觉升级 |
| 四周头像轨道 | 学生头像分布在上下左右四周 | 新增原型 |
| 拖拽解锁 | 长按自己的头像，拖入中心学习光环 | 新增核心交互 |
| 身份确认 | 显示当前学生头像和名字，只确认本次互动身份 | 新增核心交互 |
| 插件选择 | AI 问答、听写播报、课文跟读等短时互动入口 | 保留已有能力并视觉化 |
| 自动回到待机 | 互动结束或超时后回到公共展示 | 新增基础规则 |

### 5.2 平板端不能展示

- 学生分数。
- 单个学生任务完成度。
- 单个学生错题详情。
- 家长联系方式。
- 长期学生档案全文。

### 5.3 第一版可用插件

| 插件 | V1 处理 |
| --- | --- |
| AI 问答 | 可作为实际入口 |
| 听写播报 | 可作为实际入口 |
| 课文跟读 | 可作为实际入口 |
| 课堂投票 | 只做入口或展示态 |
| 今日鼓励 | 只做入口或展示态 |
| 小组协作 | 只做入口或展示态 |

## 6. 电视动态屏 V1 功能清单

电视动态屏面向家长、来访者和现场展示，第一版重点是“数据动态化”和“信任感”，不是学生个人展示。

### 6.1 必做模块

| 模块 | 展示内容 |
| --- | --- |
| 今日学习运行概览 | 今日任务数、提交数、AI 处理数、老师复核数、归档数 |
| AI 学习中枢 | 教师发布、学生提交、AI 识别、老师复核、学生反馈、阶段归档 |
| AI 处理队列 | 识别中、待复核、已反馈、已归档的匿名状态 |
| 多年级任务分布 | 不同年级今日任务、提交、复核的整体分布 |
| 实时学习动态 | 匿名事件，如“英语词汇任务已提交”“数学错题已进入复核” |
| 学科知识互动热力 | 语文、数学、英语等学科的知识点互动热度 |

### 6.2 展示原则

电视端不显示学生头像墙，因为当前是多年级混合使用，不适合把某个年级或个人放在公共展示中心。

电视端只显示：

- 整体数量。
- 匿名事件。
- 多年级分布。
- 学科热力。
- AI 流程。
- 老师复核节点。

电视端不显示：

- 学生头像墙。
- 学生姓名。
- 个人分数。
- 排名。
- 个人完成度。
- 单个学生错题。

### 6.3 动态化表现

第一版动态屏需要比静态看板更丰富，建议保留这些动态表达：

- 数字轻微滚动刷新。
- AI 流程线流动。
- 队列状态逐条滚动。
- 多年级分布图动态变化。
- 学科热力色块有轻微呼吸。
- 匿名学习事件轮播。

## 7. 教师端 V1 功能清单

教师端第一版以实用为主，不需要作为最强展示端，但必须承担控制和复核责任。

### 7.1 必做模块

| 模块 | 功能内容 | V1 处理 |
| --- | --- | --- |
| 教师登录 | 电话、姓名、教师专属码登录 | 保留 |
| 工作台 | 服务状态、今日任务、待复核、学生概览 | 保留并轻改 |
| 学生权限 | 学生注册、专属码、登录权限、档案入口 | 保留 |
| 今日任务 | 给学生发布任务 | 保留 |
| 教材资料 | 教材扫描、章节维护、打开教材、资料上下文 | 保留 |
| 生成打印 | 练习/小测/试卷生成，PDF 草稿审查，正式题目与解析 PDF 导出 | 保留 |
| 批改复核 | 上传批改、AI 初判、老师复核、标记完成 | 保留 |
| 学生档案 | 生成档案草稿、老师确认发布、查看学生归档数据 | 保留 |
| 课堂设备 | 平板锁定/解锁、听写、跟读、播报、大屏连接入口 | 保留 |
| 系统状态 | AI 服务状态、审计记录、运行状态 | 保留 |

### 7.2 新增轻量控制

| 控制项 | V1 处理 |
| --- | --- |
| 打开电视动态屏 | 教师端增加入口或预览链接 |
| 平板展示模式 | 简单切换常规待机、家长参观、课堂互动 |
| 平板锁定/解锁 | 复用已有设备锁定能力 |
| 插件开关 | 第一版只做简单可用/不可用，不做复杂规则 |

## 8. 第一版推荐开发顺序

### Step 1：确认功能清单与信息架构

先确认本清单中哪些属于第一版必做，哪些继续暂缓。

### Step 2：主题 UI 落地

把已确认的主题 UI 迁移到真实 Web/小程序页面中，优先学生端和平板端。

### Step 3：电视动态屏独立页面

先做 Web 大屏页面，使用已有 bootstrap、任务、提交、复核、审计数据做聚合展示。

### Step 4：平板拖拽解锁原型

实现四周头像轨道、拖拽吸附、身份确认、插件选择和自动回到待机。

### Step 5：学生端模块化首页

把学生端首页调整为几大模块入口，进入模块后再做具体功能。

### Step 6：教师端控制入口

增加电视动态屏入口、平板展示模式入口和基础插件开关。

### Step 7：真实数据替换与演示链路

把电视动态屏和平板端从模拟数据逐步替换为真实聚合数据，形成可演示闭环。

## 9. 第一版验收标准

第一版完成后，应该能演示以下完整流程：

1. 教师登录后能管理学生、发布任务、生成练习、上传批改、复核结果。
2. 学生登录后能查看今日任务、使用 AI 问答、使用英语词汇助手、拍照提交、查看档案反馈。
3. 平板端能展示公共待机页，学生能拖拽自己的头像进入中心光环完成本次互动身份确认。
4. 平板端解锁后能选择 AI 问答、听写播报、课文跟读等短时互动插件。
5. 电视动态屏能展示多年级匿名化动态数据，并体现 AI 识别、老师复核、反馈归档的流程。
6. 公共展示不出现排名、个人分数、个人完成度和敏感信息。
7. 整体 UI 风格统一，有清晰的温和科技感和 AI 运行感。
