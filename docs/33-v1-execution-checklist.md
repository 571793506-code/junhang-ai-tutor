# 第一版开发执行清单

## 1. 执行策略

第一版建议采用“先 Web 验证，再小程序迁移”的方式推进。

原因：

1. Web 端已经有三端角色切换，适合快速验证学生端、教师端、平板端和电视动态屏的信息架构。
2. 电视动态屏更适合先做成 Web 大屏页面，方便投到电视或浏览器展示。
3. 平板拖拽交互在 Web 中更容易快速调试，再迁移到小程序端。
4. 学生端和教师端已有小程序页面，确认视觉和模块后再迁移，风险更低。

## 2. 优先级定义

| 优先级 | 含义 |
| --- | --- |
| P0 | 第一版必须完成，否则无法形成展示和使用闭环 |
| P1 | 第一版建议完成，可以显著提升体验和信任感 |
| P2 | 保留入口或概念展示，暂不做完整业务闭环 |
| Later | 后续版本再做 |

## 3. 第一阶段：主题 UI 与真实功能对齐

目标：把当前主题预览沉淀为真实页面的设计基准，并避免出现与小程序现有能力不一致的模块。

### 3.1 任务清单

| 优先级 | 任务 | 输出 |
| --- | --- | --- |
| P0 | 确认小程序统一登录入口 | 学生、教师、平板端三类身份入口和对应登录字段 |
| P0 | 确认学生端首页模块结构 | 今日任务、AI 问答、英语词汇、拍照提交、学生档案、互动扩展 |
| P0 | 确认平板端公共展示结构 | 公共待机、四周头像、中心学习光环、插件选择 |
| P0 | 确认电视动态屏结构 | 今日概览、AI 中枢、队列、年级分布、匿名动态、学科热力 |
| P0 | 确认教师端控制结构 | 工作台、学生权限、今日任务、生成打印、批改复核、学生档案、教材资料、课堂设备、电视动态屏、系统状态 |
| P1 | 建立统一视觉变量 | 颜色、卡片、按钮、标签、数据图、动态效果 |

### 3.2 验收标准

- 主题 UI 里的模块名称和真实小程序功能一致。
- 小程序启动页只展示身份选择和对应登录表单。
- 学生端不出现第一版无法支撑的主功能。
- 电视端不出现学生头像墙、排名、个人完成度。
- 平板端明确是公共设备，不进入学生完整个人主页。

## 4. 第二阶段：电视动态屏落地

电视动态屏是给家长看的第一印象页面，建议优先落地。

### 4.1 页面定位

第一版做成独立 Web 大屏页面，适合浏览器全屏或电视投屏。

建议入口：

- Web 端增加“电视动态屏”视图。
- 教师端工作台增加“打开电视动态屏”按钮。

### 4.2 模块清单

| 优先级 | 模块 | 数据来源 | 第一版做法 |
| --- | --- | --- | --- |
| P0 | 今日学习运行概览 | bootstrap tasks、submissions、review、reports | 聚合数量 + 动态数字 |
| P0 | AI 学习中枢 | tasks、submissions、review、profile publish | 流程节点 + 动态流线 |
| P0 | AI 处理队列 | submissions、review 状态 | 匿名状态队列 |
| P0 | 多年级任务分布 | students.grade + tasks | 条形图或分布图 |
| P0 | 实时学习动态 | logs、audit events | 匿名事件流 |
| P0 | 学科知识互动热力 | tasks、corrections、qa、submissions | 学科 + 知识点热力 |
| P1 | 自动刷新 | bootstrap/audit | 30 到 60 秒刷新一次 |

### 4.3 数据原则

- 可以先用真实数据聚合 + 少量展示补全。
- 数据不足时显示“今日记录正在生成”，不要显示空白。
- 所有事件匿名化，只显示学科、年级、任务类型和流程状态。

### 4.4 验收标准

- 电视端在 16:9 大屏下内容饱满，不空泛。
- 页面持续有动态：数字、流线、队列、热力、事件。
- 家长能看懂 AI 在做什么，老师在哪里复核。
- 不暴露学生个人信息。

## 5. 第三阶段：平板公共端拖拽解锁

平板端是学生现场参与感的核心。

### 5.1 页面状态

| 状态 | 内容 | 优先级 |
| --- | --- | --- |
| 公共待机 | 今日主题、整体概览、AI 工作流、四周头像、插件栏 | P0 |
| 长按拖拽 | 头像放大、轨迹、中心光环高亮 | P0 |
| 吸附确认 | 头像进入学习光环，显示学生姓名和本次互动确认 | P0 |
| 插件选择 | AI 问答、听写播报、课文跟读 | P0 |
| 回到待机 | 超时或结束后自动恢复 | P1 |

### 5.2 交互规则

- 学生头像分布在上下左右四周。
- 长按约 0.5 秒后进入拖拽态。
- 拖到中心学习光环附近时出现吸附反馈。
- 松手后只确认本次互动身份。
- 本次互动结束后不保留个人页面。

### 5.3 插件边界

| 插件 | 第一版状态 |
| --- | --- |
| AI 问答 | 实际可用 |
| 听写播报 | 实际可用或接已有入口 |
| 课文跟读 | 实际可用或接已有入口 |
| 课堂投票 | 展示入口 |
| 今日鼓励 | 展示入口 |
| 小组协作 | 展示入口 |

### 5.4 验收标准

- 学生能明确知道“拖自己的头像到中心”。
- 拖拽、吸附、确认的反馈足够清楚。
- 公共屏不展示成绩、排名和个人完成度。
- 解锁后不会进入完整学生端。

## 6. 第四阶段：学生端模块化首页

学生端第一版要围绕已有功能，不做过多新系统。

### 6.1 首页模块

| 优先级 | 模块 | 第一版处理 |
| --- | --- | --- |
| P0 | 今日任务 | 显示任务数量、待完成、状态，点击进入任务页 |
| P0 | AI 问答 | 显示可用状态，点击进入问答页 |
| P0 | 英语词汇 | 显示词汇助手入口，点击进入词汇页 |
| P0 | 拍照提交 | 显示提交入口和最近提交状态 |
| P0 | 学生档案 | 显示老师复核后的阶段反馈入口 |
| P1 | 掌握情况 | 语文、数学、英语概览，不做压力化展示 |
| P2 | 互动扩展 | 作为老师开启后的活动入口 |

### 6.2 页面表达

- 首页采用“模块选择 -> 进入模块 -> 执行操作”的结构。
- 今日任务和学生档案强调老师发布、老师复核。
- AI 问答强调思路引导，不强调替学生直接写答案。
- 互动扩展默认低调，不抢主流程。

### 6.3 验收标准

- 学生和家长能一眼看到今天该做什么。
- 所有入口都对应当前小程序已有页面或明确的后续扩展。
- 不出现强排名、强刺激积分、公开 PK。

## 7. 第五阶段：教师端控制入口

教师端不作为第一版展示重点，但必须让老师能控制流程。

### 7.1 必做

| 优先级 | 功能 | 第一版处理 |
| --- | --- | --- |
| P0 | 学生权限 | 保留并优化入口 |
| P0 | 今日任务发布 | 保留 |
| P0 | 练习/小测/试卷生成 | 保留 |
| P0 | 拍照上传批改 | 保留 |
| P0 | 复核队列 | 保留 |
| P0 | 档案草稿与发布 | 保留 |
| P1 | 打开电视动态屏 | 新增入口 |
| P1 | 平板展示模式 | 常规待机、家长参观、课堂互动 |
| P2 | 插件开关 | 简单开关，不做复杂规则 |

### 7.2 验收标准

- 老师能从教师端打开或预览电视动态屏。
- 老师能理解平板当前处于什么展示模式。
- AI 生成内容必须经过老师复核才能发布到学生端或档案。

## 8. 数据与接口拆解

### 8.1 先复用的现有接口

| 场景 | 接口能力 |
| --- | --- |
| 初始数据 | `/api/bootstrap` |
| 服务状态 | `/api/status`、`/api/ai/status` |
| 学生登录 | `/api/student-login` |
| 教师登录 | `/api/teacher-login` |
| 平板登录 | `/api/classroom/device-login` |
| AI 问答 | `/api/ai/qa` |
| 教师任务 | `/api/teacher/tasks` |

| 提交上传 | `/api/submissions/batches` |

| 学生档案 | `/api/students/:studentId/profile/*` |
| 平板设备 | `/api/classroom/devices/:deviceId` |

| 审计 | `/api/admin/audit` |

### 8.2 第一版可新增的轻量接口

| 接口方向 | 用途 | 优先级 |
| --- | --- | --- |
| TV 聚合数据 | 给电视动态屏返回匿名统计 | P1 |
| 平板展示配置 | 返回当前展示模式和插件开关 | P1 |
| 平板互动事件 | 记录头像拖拽解锁和插件使用 | P1 |

如果时间紧，第一版可以先在前端从 bootstrap 聚合电视数据，后续再抽成正式 API。

## 9. 推荐开发顺序

1. 固化主题 UI、模块命名和统一登录入口。
2. 做电视动态屏 Web 页面。
3. 做平板端拖拽解锁 Web 原型。
4. 调整学生端首页为模块化结构。
5. 给教师端增加电视动态屏和平板展示模式入口。
6. 先迁移小程序统一登录入口，再迁移学生端首页和平板端 dashboard。
7. 把模拟动态数据逐步替换为真实聚合数据。

## 10. 第一版风险控制

| 风险 | 控制方式 |
| --- | --- |
| 功能过多导致第一版拖慢 | P0 先完成，P2 只做入口 |
| 公共屏造成学生压力 | 不显示排名、分数、个人完成度 |
| 电视屏显得空泛 | 增加动态数据、流程、队列、热力和匿名事件 |
| 学生端偏离已有功能 | 首页入口严格对应当前已有页面 |
| AI 内容不够可信 | 强调老师复核、阶段归档、可追踪 |
| 平板是共享设备 | 只做本次互动身份确认，不做个人主页 |

## 11. 下一步可直接开始的开发任务

### 11.1 最推荐先做

1. 在 Web 端新增真实“电视动态屏”页面或视图。
2. 把主题预览中的电视动态屏布局迁移过去。
3. 使用 bootstrap 数据做匿名聚合。
4. 从教师端增加“打开电视动态屏”入口。

### 11.2 第二个开发任务

1. 在 Web 端课堂/平板视图中实现四周头像轨道。
2. 实现拖拽进入中心学习光环。
3. 完成本次互动身份确认。
4. 展示可用插件。

### 11.3 第三个开发任务

1. 重构学生端首页为模块卡片。
2. 保留现有页面跳转。
3. 把互动扩展放到次级位置。
4. 统一温和科技感视觉。
