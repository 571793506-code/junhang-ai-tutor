# 项目踩坑审查与防护清单

本文记录“君航 AI 助教”当前仓库已经踩过或已经暴露风险的问题，用于后续开发、联调和 Codex 对话前快速复核。范围来自现有项目规则、运行手册、编码守卫文档和当前 `git status --short` 状态。

## 开工前检查

每次继续操作前先做这几步：

1. 运行 `git status --short`，确认本次要碰的文件范围。
2. 先读 `AGENTS.md`、`README.md`、本文，以及本次任务相关的 runbook。
3. 明确本次成功标准：要改什么、不要改什么、用什么命令验证。
4. 涉及中文文案、提示词、生成内容、HTML/PDF 源、历史备份时，默认最后运行 `.\jh.cmd check:encoding`。
5. 涉及生成、批改、资料上下文、教师复核或导出时，优先运行 `cmd /c npm.cmd run check:content-context`、`cmd /c npm.cmd run check:content-upload-ui`、`cmd /c npm.cmd run check:teaching-content`。
6. 准备 stage 前只使用显式路径，不使用 `git add .`。

## 按任务类型的验证要求

### 文档、规则、中文文案

- 修改后运行 `.\jh.cmd check:encoding`。
- 涉及历史导出、备份、生成 HTML/PDF 源时运行 `.\jh.cmd check:encoding:history`。
- 如果终端显示乱码，先确认读取方式，不要直接重写文件。

### API、服务层、数据库、共享包

- 优先运行 `.\jh.cmd check:api`。
- 涉及生成、资料上下文、复核或导出时，补跑 `cmd /c npm.cmd run check:content-context` 和 `cmd /c npm.cmd run check:teaching-content`。
- 检查返回体是否按角色过滤字段。

### Web 原型

- 运行 `npm.cmd run typecheck --workspace apps/web`。
- 说明该能力如何复用 API、服务层或数据契约，避免只写在页面状态里。

### 小程序

- 当前已恢复继续搭建。
- 小程序页面、路由、样式、API 封装或端侧交互变更后，运行 `.\jh.cmd check:miniprogram-js` 和 `.\jh.cmd check:encoding`。
- 涉及资料上下文、生成、批改、学生档案或教师复核时，同时对照 `docs/14-api-contract.md` 和 `docs/44-miniprogram-migration-runbook.md`，确认小程序只提交必要参数并复用后端能力。

## 当前结论

本项目下一阶段最重要的防护不是继续堆功能，而是收窄边界、保持 Git 可追踪、把核心逻辑留在服务层、让 AI 输出先成为可复核草稿，并用现有检查命令守住乱码、权限、生成质量和导出链路。
