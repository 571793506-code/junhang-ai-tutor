`AGENTS.md` project rules take priority. Before editing, read the `skills/grading/SKILLS.md` Playbook. For cross-module changes, read every affected module Playbook.

For generated materials, load the `generation` contract and read `gradingSourcePackage` / `questionLayoutManifest` before grading. For external materials, stay on the reference-answer path. When confirmed results feed a profile, load `skills/student-profile/SKILLS.md` after teacher confirmation.

Minimum verification: `cmd /c npm.cmd run check:api`.

Read `skills/grading/references/runtime-rules.md` for shared evidence, scoring and confirmation rules. Change teaching details there, then verify `cmd /c npm.cmd run check:skills`. Runtime loading belongs in the AI layer; uploads cannot select rules or grant confirmation. Model routing and budgets belong in `packages/ai/src/model-policy.js`.

For a carried calculation error, compare the visible steps with the source rubric's method, calculation and final-answer awards. Apply its explicit carry-forward policy; when the missing policy changes the score, retain `uncertain` with `score:null`. A correct final answer cannot erase visible incorrect work. See the runtime rules for the boundary; synthetic diagnostic scores are not teacher gold.

For shared workflow commands, read the "Shared workflow API and CLI" section of `docs/14-api-contract.md` and the current implementation plan. `node scripts/teaching-workflow.mjs` uses the same HTTP API and the teacher session named by `TEACHING_SESSION_FILE`. Create grading from a registered studentId and submissionId; the server reads the answer source, original recognition and evidence binding. Fetch the current revision before submitting a command; use stable question IDs and preserve operationKey and expectedRevision when replaying the same operation. Revise selected questions with instruction, or provide an explicit manual patch. Confirmation requires an explicit teacher decision; trusted server archives can reuse unchanged confirmation. Imported JSON cannot grant confirmation, and confirm does not trigger the separate archive command. The Web workbench and executor/validator adapters are enabled in the current local business deployment after the 2026-09-29 schema migration and Prisma Client refresh. Verify the current environment rather than assuming this local enablement applies to every deployment. The 16-question real grading run passed teacher confirmation, separate archive, database idempotency and profile evidence admission on 2026-10-10; see `docs/teaching-workflow-acceptance.md`. This single run does not establish overall OCR or grading accuracy; deferred holdout tasks remain deferred.

For quality evaluation, follow the Playbook's gold collection and independent replay commands. Teacher-confirmed gold supplies expected labels, never actual predictions. Evaluate only replay results bound by evaluationRun; missing or invalid execution evidence yields unknown metrics, and counts.evaluatedCases records coverage. The synthetic example is a gold contract fixture without predictions, not accuracy evidence.

For model timeouts, inspect the internal attempt.transportDiagnostics last phase: request_started means no response headers observed, response_headers means body completion was not observed, and response_body_complete means transport completed. These observations do not establish the upstream root cause. Retain unknown status/usage when absent; do not infer HTTP 503 from a deadline. Diagnostics are server-owned and excluded from product responses and model candidate fields. A minimal synthetic probe confirms current connectivity only, not full grading availability or accuracy.

Collection restores missing legacy question types only from source-aligned registered items or validated immutable archive bindings. Preserve archived types when live items change; never derive scoring types from OCR or question-number ranges. This enriches evaluation input only, without rewriting source packages, teacher labels or archives. Missing original shared materials and print geometry remain unknown.

For answer-recognition corrections, use `revise` with one targetQuestionId and `patch:{type:"correct_recognition",questionId,value:{studentAnswer}}`. Read the Playbook's "持续批改工作台与对话共用动作" section before correcting recognition or scores. Correction always regrades only that question through the shared service; changing studentAnswer in a full question patch also regrades. Missing recognition is null; an empty string is allowed only after the teacher has checked an actually blank answer. Keep measured OCR confidence and image coordinates intact. A score-only patch does not call a model; it still clears that question's confirmation. For Web changes, run `check:web:teaching-grading` with the existing browser runtime as described in the plan.
